## 内容落哪份文件

新增内容前先判断落哪份，别就近塞——两处不互相复述：

- **规则与它失效时的机制** → `design/` 的对应文件
- **实测输出、源码引用、被排除的做法** → `decisions.md`
- **怎么验、门禁挡什么** → `gates.md`
- **一次性的过程记录** → `history.md`（**是记录不是约束**；任何一条在其中沉淀出的通用规则，要么进 `decisions.md`、要么进 `CLAUDE.md` 红线，不靠读日志来生效）

## 两条写作约定

- **中文标点按 GB/T 15834 用全角**：`，；：（）“”` 不写半角，`。、「」——……` 本就是全角；破折号 `——` 占两个字位、**前后不加空格**。三类**不**转：数字千分位（`1,048,945`）、成段英文引文的内部、代码块与行内代码里的一切。另有一条不属于标点却同源：**段落不要在两个汉字之间硬换行**——markdown 会把那个换行渲染成一个可见空格，源码里看不出来，只有在网页上才看得见。**这条没有门禁**，改文档时靠自觉。
- **`CLAUDE.md` 的预算是 ≤ 200 行，且一条规则占一行。两半必须同时成立，缺一则度量失效**：行数能被「把十几条规则塞进一个 bullet」轻易做低，那样的文件行数好看而实际不可扫读。**禁止再给它补字节 / KB 上限**——中文 UTF-8 3 字节/字，字节维度远早于行数触顶，一旦并设，真正生效的约束就只剩字节，而省字节最省事的手段恰恰是把多条规则挤进一行长句。超出预算时**先问「这段能不能下沉到本目录」，而不是接着往下写**；红线与路由表不参与裁剪，可裁的是能从代码库或 git log 推导出来的内容。
