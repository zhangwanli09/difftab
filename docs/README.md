# difftab 文档索引

**需求与设计的唯一事实来源是本目录。** 需求要变，先改这里再改代码。常驻上下文是仓库根的 [`CLAUDE.md`](../CLAUDE.md)（摘要 + 红线 + 路由表）；本目录的文件**按需读取**，不必通读。

## 改这块 → 读哪份

**读侧路由表只有一份，在 [`CLAUDE.md` 第 4 节](../CLAUDE.md)。** 本目录不复述它——两份并列的路由表没有任何门禁看得见，而它已经漂过一轮：同一份文件在两处的措辞与覆盖范围都不同，且常驻的那份反而缺了 `decisions.md` 与 `history.md` 两行。本文件只管**写侧**：新内容该落哪份。

发布**步骤**在 [`../RELEASING.md`](../RELEASING.md)，对外的贡献者说明在 [`../CONTRIBUTING.md`](../CONTRIBUTING.md)。

## 内容落哪份文件

新增内容前先判断落哪份，别就近塞——两处不互相复述：

- **规则与它失效时的机制** → `design/` 的对应文件
- **实测输出、源码引用、被排除的做法** → `decisions.md` **该域那一节**（七节之一，别在文件末尾另起一摊）
- **怎么验、门禁挡什么** → `gates.md`
- **一次性的过程记录** → `history.md`（**是记录不是约束**；任何一条在其中沉淀出的通用规则，要么进 `decisions.md`、要么进 `CLAUDE.md` 红线，不靠读日志来生效）

三条结构上的约定：

- **`design/` 按领域分文件，一份撑到约 15k 字符就再拆**（当前最大的是 `design/build.md`）。拆分的全部意义是让「只读用得着的那份」在工具层面真的只付一份的代价——读取的最小单位是文件，一份长回四五万字符，路由表就退化成一句安慰。
- **`decisions.md` 不按文件拆，按小节拆，入口一律是锚点。** 它是全目录最大的一份，而任一个域只占其中十分之一到五分之一——按域切成七份文件会让「同一条证据横跨两个域」无处可放。折中是：**七个小节各自自带本域的「被排除的做法」分表，`design/` 一律以 `../decisions.md#<小节>` 链进去。** 与上一条的拆分不同，**这个折中换不来读取量上的节省**：读取的最小单位是文件，锚点只保证一眼落到那一节，因此那七节各自都要能被单独读懂。该文件的小节标题则写成纯词组、不带括号与标点——锚点是靠标点剥离规则算出来的，链错了不会有任何东西响。
- **不重建逐条勾选的验收清单与阶段排期。** 阶段推进已经结束，「怎么验」由 `gates.md` 以「门禁 → 挡住哪条静默故障」的形式承接；再开一份带 `[x]` 的清单，等于把一个没有读者的东西重新养起来。

## 四条写作约定

- **中文标点按 GB/T 15834 用全角**：`，；：（）“”` 不写半角，`。、「」——……` 本就是全角；破折号 `——` 占两个字位、**前后不加空格**。三类**不**转：数字千分位（`1,048,945`）、成段英文引文的内部、代码块与行内代码里的一切。**范围是全仓的中文，不止 `docs/`**：代码注释与中文字符串里的句读同样用全角，判据是「这个标点落在注释或字符串里」而不是「它旁边有汉字」——语法位置上的半角照旧（`{ 慢写: x }` 的冒号、`:root`、`?.`），注释里的行内代码（`light-dark(浅, 深)`）也照旧。另有一条不属于标点却同源：**段落不要在两个汉字之间硬换行**——markdown 会把那个换行渲染成一个可见空格，源码里看不出来，只有在网页上才看得见（折行正好落在 `——` 旁边同理）。**这一条都没有门禁**，改文档与改注释时靠自觉。
- **`CLAUDE.md` 的预算是 ≤ 200 行，且一条规则占一行。两半必须同时成立，缺一则度量失效**：行数能被「把十几条规则塞进一个 bullet」轻易做低，那样的文件行数好看而实际不可扫读。**禁止再给它补字节 / KB 上限**——中文 UTF-8 3 字节/字，字节维度远早于行数触顶，一旦并设，真正生效的约束就只剩字节，而省字节最省事的手段恰恰是把多条规则挤进一行长句。超出预算时**先问「这段能不能下沉到本目录」，而不是接着往下写**；红线与路由表不参与裁剪，可裁的是能从代码库或 git log 推导出来的内容。
- **读侧路由表（「改这块 → 读哪份」）只有一份，在 `CLAUDE.md` 第 4 节。** 别在本目录里再养一份：路由表漂移的症状是有人被指到错的文件上，而那既不报错也没有门禁，与本节标点那条同属「靠自觉」的一类。本目录只留写侧路由（内容落哪份）。
- **`CLAUDE.md` 第 5 节红线与 `design/` 刻意重复，不因「顶层文件应当只做路由」而裁剪。** 收录判据是「违反后不报错、只是静默出错」——这类条目必须在常驻上下文里，等读者路由到对应 `design/` 文件时已经晚了。**要裁的是能从代码库或 git log 推导出来的内容，不是红线。**写下这条是因为「顶层只写选择器」是个流传很广的说法，而按它裁掉红线不会有任何东西变红。
