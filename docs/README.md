# difftab 文档索引

**需求与设计的唯一事实来源是本目录。** 需求要变，先改这里再改代码。常驻上下文是仓库根的 [`AGENTS.md`](../AGENTS.md)（摘要 + 横切红线 + 必读路由表；同目录的 `CLAUDE.md` 只是一行 `@AGENTS.md` 的导入壳）；本目录的文件**按需读取**，不必通读。

## 改这块 → 读哪份

**读侧路由表只有一份，在 [`AGENTS.md` 第 4 节](../AGENTS.md)**，本目录不复述——两份路由表漂开时没有任何门禁看得见。本文件只管**写侧**：新内容该落哪份。

发布**步骤**在 [`../RELEASING.md`](../RELEASING.md)，对外的贡献者说明在 [`../CONTRIBUTING.md`](../CONTRIBUTING.md)。

## 内容落哪份文件

新增内容前先判断落哪份，别就近塞——两处不互相复述：

- **规则与它失效时的机制** → `design/` 的对应文件
- **实测输出、源码引用、被排除的做法** → `decisions/` 下**该域那一份**（一域一份，横跨两域的放主要相关那份、另一份链过去）
- **怎么验、门禁挡什么** → `gates.md`
- **一次性的过程记录** → `history.md`（**是记录不是约束**；从中沉淀出的通用规则要么进 `decisions/`、要么进 `design/` 或 `AGENTS.md` 红线）。**发布不在这里逐版记**：变更日志是 release-please 生成的 `../CHANGELOG.md`，发版时新撞上的坑直接进 `../RELEASING.md`
- **违反后静默出错的规则（红线）** → 横切的进 `AGENTS.md` 第 5 节，只在改某个目录时才会违反的进该目录对应的 `design/` 文件（判据见下方第四条约定）

两条结构上的约定：

- **`design/` 与 `decisions/` 都按领域分文件，单份以约 15k 字符为软目标**：读取的最小单位是文件，一份长回四五万字符，路由表就退化成一句安慰。超出时先删能从代码或测试推导出来的东西（类名串、像素数值与加法、「某测试钉着」的旁注），只留规则、判据与失效时的症状（`design/` 正文里标「有断言」的条目由 `test/unit/` 钉住、不进红线）；仍明显偏大、且能切出一块自成一体的领域时再拆，并在 `AGENTS.md` 第 4 节补一行路由。
- **不重建逐条勾选的验收清单与阶段排期。** 「怎么验」由 `gates.md` 以「门禁 → 挡住哪条静默故障」的形式承接。

## 四条写作约定

- **中文标点按 GB/T 15834 用全角**：`，；：（）“”` 不写半角，`。、「」——……` 本就是全角；破折号 `——` 占两个字位、**前后不加空格**。三类**不**转：数字千分位（`1,048,945`）、成段英文引文的内部、代码块与行内代码里的一切。**范围是全仓的中文，不止 `docs/`**：代码注释与中文字符串里的句读同样用全角，判据是「这个标点落在注释或字符串里」而不是「它旁边有汉字」——语法位置上的半角照旧（`{ 慢写: x }` 的冒号、`:root`、`?.`），注释里的行内代码（`light-dark(浅, 深)`）也照旧。另有一条不属于标点却同源：**段落不要在两个汉字之间硬换行**——markdown 会把那个换行渲染成一个可见空格，源码里看不出来，只有在网页上才看得见（折行正好落在 `——` 旁边同理）。**这一条都没有门禁**，改文档与改注释时靠自觉。
- **`AGENTS.md` 的预算是 ≤ 200 行，且一条规则占一行。两半必须同时成立**：只看行数时，把十几条规则塞进一个 bullet 就能做低，文件却不可扫读。**禁止再给它补字节 / KB 上限**——中文 UTF-8 3 字节/字，字节维度远早于行数触顶，并设后真正生效的只剩字节，而省字节最省事的手段恰恰是把多条规则挤进一行长句。超出预算时**先问「这段能不能下沉到本目录」**；可裁的是能从代码库或 git log 推导出来的内容。
- **全仓只有根目录一份 `AGENTS.md`**，不建子目录的嵌套 `AGENTS.md` / `CLAUDE.md`，也不用某个 agent 私有的规则格式：分层靠「根里的必读路由 → `design/`」，任何 agent 只要读了根文件就拿得到。同理**不在 `src/` / `test/` 下建模块 README**：规则与判据进 `design/`，文件级的导览交给代码与注释——第三处知识没有路由指过去，改 `design/` 时不会有人想起去同步它。
- **红线按作用域落位：横切的常驻 `AGENTS.md` 第 5 节，目录作用域的写在 `design/` 正文里，由第 4 节的必读路由表保证先读到。** 横切的判据是「违反时可能根本没碰某个特定目录，或落在根级文件上」——这类等读者路由过去就晚了，必须常驻。目录作用域的那类只在改那块代码时才会违反，而改之前第 4 节要求先读对应文件，所以**第 4 节那张表本身是红线，不参与裁剪**；往 `design/` 里写这类规则时，规则、判据与失效症状三样都要写全，因为不会再有第二份摘要兜底。
