# 前端：界面文案、页面骨架与变更列表

> **TypeScript + Preact + @preact/signals，经 Vite 构建为静态产物**，由后端直接托管。diff 怎么渲染在 [`diff-render.md`](diff-render.md)，配色与层叠隔离在 [`style.md`](style.md)。选型与被排除的做法见 [`../decisions.md` 的「前端渲染与体积」](../decisions.md#前端渲染与体积)，门禁见 [`../gates.md`](../gates.md)。

## 界面文案与术语

**界面文案一律英文，`<html lang>` 为 `en`。** 判据是**产品表面与文档分属两个读者**：`docs/` 与代码注释写给维护者，中文；而分发形态是 npm 全局包，CLI 的 `--help`、退出提示、版本守卫报错本来就是英文，界面是同一个表面上唯一说中文的部分。中文读者由 `README.zh-CN.md` 承接。首版不做语言切换。

- 术语跟 git 自己的用词走（`Staged` / `Unstaged` / `Untracked` / `Conflicted` / `Detached HEAD` / `Rebasing`），不自造同义词——用户是拿它对照 `git status` 看的。
- **判据是「`dist/web/` 三个产物里的 CJK 字符数为 0」**，不是逐个文件翻源码：漏网的最可能形态是**不长在 JSX 上的那几条**（`state/store.ts` 的错误文案就这么漏过一次），而按文件翻依赖「想不想得起来」。前端产物里本来就不该有中文——注释在构建期已去掉，diff2html / hljs 也不带。
- **后端产物用不了这个判据**：`dist/server/main.js` 不压缩不混淆，中文注释原样留着正是为了可审计。那一侧的用户可见文案是 `sendError` 与各 `*Error` 的字面量，归 `test/unit/server/`。
- 改文案要同步改 `test/unit/web/` 里的可见文本断言。这一条**会报错**，不进红线。

## 页面骨架

**外壳是行向 flex：左栏一列（顶栏 → 错误条 → 变更列表 → 状态条），右边是 diff 面板，面板自屏幕顶端满高到底。** 顶栏不横跨全屏——它归左栏。

- **顶栏里是项目名 + 主题开关**，两样而已。项目名是 `RepoState.repoName`（工作区根目录名，与标签页标题里的是同一份），位置对应 VS Code 侧栏顶端那行文件夹名：这一栏要回答的是「我在看哪个项目」，产品名答不了，而它在标签页标题里仍留着一份。拿不到仓库名时退回纯 `difftab`（**共用的是 `PRODUCT_NAME` 那一串，判据两边各写一次**——两处的组合本就不同，理由在 `state/title.ts`）：「第一份 state 还没到」与「根目录没有 basename」在这里同样合成一种情况。
- **`truncate` 必须落在装项目名的那个 `span` 上，不是顶栏本身**：产品名长度恒定，目录名可以任意长，不裁时被撑开的不是顶栏而是文字自己——不带断点的长名漫过右边框压到 diff 面板上，带连字符的则折成第二行把顶栏撑高。顶栏成为 flex 容器之后**这条得再钉一遍**：`truncate` 留在容器上不起作用（子项的自动最小尺寸会把它撑开），症状与从前一模一样，而 `truncate` 字样还在原地，看上去像是已经处理过了。开关那侧 `shrink-0`，被裁的永远是名字不是按钮。
- **分支状态与监听标注放在左栏底部的状态条**上（位置对应 VS Code 的 status bar）：三样挤进同一行时，320px 减去项目名与间距只剩不到 180px，而收缩优先级由既有机制定死——徽章 `shrink-0`、分支名 `min-w-0` + `truncate`，于是先被裁掉的恰恰是分支名，而它正是这一段存在的理由。沉到状态条后它独占一行。
- **顶栏之下是一行两个 tab（`Changes` / `Files`）**，排在错误条之上。位置对应 VS Code 的 activity bar，**画成两枚紧挨着靠左的图标、但仍是横排一行，不切一列竖排**：竖排要再占一列宽，而 320px 的侧栏里那一列是从文件名身上扣的，两个视图也用不着一整列。两枚按钮各按自身宽度排、不平分整栏——通栏那条细线是行自己的 `border-b`，选中下划线只是画在它上面的一小段，平分时那一段有半栏宽，看着不像指示器像第二条分隔线。**「画在它上面」要靠 `-mb-px` 才成立**：两条边默认上下相邻而非重叠（按钮那条画在自己 border box 内、容器那条画在其外），不压一下时选中那一段是双线、比未选中处厚一倍。**那条短线用前景色**（照 VS Code 经典 Dark+ 的 activity bar 活动边框），不用 `focus-border`：后者是「键盘焦点在这里」的颜色，而这一行的 focus-visible 轮廓正用着它，同色时两件事在页面上化成同一种蓝。默认档是 `Changes`——工具存在的理由仍是「瞥一眼改了什么」，目录树是顺带能做到的第二件事。两个视图**共用中间那一层滚动容器**，不各开一个。
- **`Changes` 那枚图标与状态条上分支名前的是同一枚**（Lucide `GitBranch`，对应 VS Code activity bar 上的 Source Control）。**「同一枚」由编译器保证**：两处 import 同一个具名组件，拼错标识符是编译错误——这比从前共用一条导出的 path 字符串强，那种做法里两份漂开时同一个概念在页面上就是两个图形，没有任何东西会响。**`<svg>` 那层外壳走共用的 `Icon`**（理由与 `Badge` 一字不差：`size` 与 `aria-hidden` 在六处各写一遍，漏掉一处不报错、也不画错，只是那一枚比旁边的大一圈，或者被读屏多读一遍）。`Files` 那枚是 `Folder`。
- **只画图标就意味着名字只能由 `aria-label` 给**（`title` 再给一份 tooltip），与顶栏那个主题开关同一条约束：掉了它读屏里就是两个无名控件，而页面上什么都看不出来。`app.test.tsx` 直接钉着这两个名字，故不进红线。
- **切 tab 不动右侧面板**：换的是侧栏在列什么，不是「用户此刻在读什么」——VS Code 里换侧栏视图同样不会换掉编辑器。写成「切到 Files 就清空右侧」时页面看着完全正常，只是每瞄一眼目录树就丢掉正在读的那份 diff。
- **错误条也在左栏内**，排在顶栏之下、列表之上：它说的是「变更列表取不到」，与列表那句兜底文案「原因写在上面了」相邻才成立；横跨全屏则会在 diff 面板顶上再切一条与 diff 无关的横杠。
- **状态条随第一份 state 一起出现**，拿不到时整条不画——与「不先画一个假分支再换掉」同一条取向。
- **分支名前面画一枚分支图标**（位置对应 VS Code status bar 最左那枚）。图形取自 **Lucide 的 `GitBranch`**（ISC），与主题开关那三枚同一套。**detached 与取不到名字时照画**——它标的是「这一栏说的是 HEAD 在哪」，那句话在三种情况下都成立，而按情况藏掉只会让状态条的左边缘忽进忽出。两个类名各挡一件只是「看着不对」的事：`shrink-0` 让 320px 里先被裁的仍是分支名；`self-center` 是因为那一行是 `items-baseline`，而替换元素的基线是它的底边——不写时图标整个坐在文字基线上，比文字高出小半个字。**两个类名都有断言**（`branch-status.test.tsx` 直接钉类名——happy-dom 没有排版引擎，能断言的只有类名在不在），故不进红线。
- **与上游的差距排成 `<behind>↓ <ahead>↑`**：behind 在前、数字在箭头前，逐字照 VS Code status bar 的 `syncLabel`（`${behind}↓ ${ahead}↑`）——这一栏存在的意义就是拿去与另一个窗口对照，两边的两个数一左一右反过来，每看一眼都要在心里翻一次。**两个 0 仍都画出来**（VS Code 在都为 0 时只留一个同步图标，这一半不跟）：「已同步」与「无上游」在页面上必须是两个样子，而无上游根本不输出 `# branch.ab`。顺序**有断言**——`branch-status.test.tsx` 拿两个不同的数一次钉住顺序与写法，故不进红线。
- **滚动的是变更列表那一层（`min-h-0 flex-1 overflow-auto`），不是左栏本身**：顶栏、错误条、状态条都 `shrink-0` 钉在原处，只有列表滚。左右两栏仍各有一个**独立的滚动容器**（右侧那个在标题栏之下，见「选中态与右侧面板」）——SSE 刷新要留住列表的滚动位置，共用一个就做不到。**列表那层必须归零自己的自动最小尺寸**（`min-h-0` 与 `overflow-auto` 各自都够，因为自动最小尺寸只在该轴 `overflow: visible` 时才解析成 min-content）：两个都没有时不报错，只是列表把整列撑高、状态条被挤出屏幕底部。
- **本节不改变 `outputFormat` 的判据**：那条量的是 diff 面板自身的 border box（见 [`diff-render.md`](diff-render.md) 的「版式按面板宽度自动切」），与左栏里放了什么、分成几段都无关。

## 变更列表

**一行的构成是「状态位 → 文件名 → 目录」。** 目录跟在文件名之后、小一号、次要色、**不带尾部斜杠**——它是独立的一段而不是与文件名连读的路径前缀。判据是**侧栏宽度固定 320px 而 `truncate` 从右边裁**：路径在前时先被裁掉的恰恰是文件名，而文件名才是用来认出这一行的东西。故空间不足时**先牺牲目录、保住文件名**（排法参照 VS Code 的 Source Control 面板）。

- **两段必须同住一个 `truncate` span**（名在前、目录作为它的行内子元素）。拆成两个平级 flex 子项**两件事一起坏、且都不报错**：
  - `overflow:hidden` 让每段各自成为 scroll container，基线改按**边框盒**合成而不再露出文字基线，`items-baseline` 于是把两段按底边对齐，字号不同时看着就是没对齐；
  - 谁先被裁只能靠 flex-basis 去调，而给目录 `flex-1` 会把它后面那段重命名标注推到侧栏最右、与它注解的文件名断开。

  同住一个 span 时两件都不必处理：两段共用一个行盒（基线是真的），而省略号在右端**天然**先吃掉排在后面的目录。（`min-w-0` 不在此列——截断盒无论一个还是两个都得给。）
- **这条规则钉的是树的形状，不是版式，所以它有断言**：`change-list.test.tsx` 的「同住一个 truncate span」一条查目录段所在的截断盒是否同时装着文件名，拆成兄弟即红。happy-dom 判不了的只剩「谁先被裁」那半条，归人工。
- 目录被裁是设计中的常态，故**整行挂 `title={file.path}`** 补一份完整路径；不挂在目录那个 span 上——它被裁到零宽时就没得可悬停了。
- **不做文件类型图标**：要么引一套 SVG 资源去顶产物体积门禁，要么自己维护一张扩展名→颜色表，而换来的只是观感。状态位仍留在**行首**——那一列定宽对齐，扫一眼比右侧对齐快，冲突行的 XY 两位也照旧印在那里。

## 选中态与右侧面板

**选中的文件不在新一份列表里了（改动被撤销、被 commit 掉），就连选中态一起清空、右侧回到空态。** 判据是**左栏此刻正在断言这些改动不存在，而右栏还在展示其中一份**——工作区整个变干净时这一点最刺眼：左边写着「Working tree clean」，右边配着一份完整补丁。早先的写法是留着最后那份 diff（「用户刚才在读的东西还在，只是左侧不再高亮」，排除理由见 [`../decisions.md` 的「前端渲染与体积」](../decisions.md#前端渲染与体积)）。

- **重命名不算消失**：改名之后选中的那个路径成了新列表里那一行的 `oldPath`，先按 `path` 找、再按 `oldPath` 找一次，命中就跟着它走到新路径上（拿到的是新条目，双路径齐全，不会退化成全新增）。那一行还在左栏列着，此时清空右侧，上面那条判据本身就不成立——而 agent 边跑边重构时这是常态。
- **在途的那次取 diff 要一并作废**：点开 X 之后、响应回来之前 X 从列表里没了，不作废的话它回来照旧写成 `ready`，右侧刚清掉又长回来——**不报错，只是清空偶尔不生效**，而复现要正好卡在一次请求的往返窗口里。作废手段就是 `loadDiff` 已有的那个请求序号，不另设机制。
- **右侧空态是两句话**：还没选过文件是 `Select a file on the left.`，工作区干净是 `Working tree clean — nothing to show.`。「没得选」与「还没选」在页面上是两件事——干净时那句「点左边一个文件」指着的是一个空列表。与左栏那句 `Working tree clean — no changes.` 刻意不逐字相同：一句说的是列表，一句说的是面板。
- **面板顶上那条路径横杠排在滚动区域之外**：面板自己是一列 flex（横杠 `shrink-0`，底下一层 `min-h-0 flex-1 overflow-auto`），滚的是下面那一层——面板里可以有几千行，滚下去之后「在看哪个文件」就再没有别处答得了。**不做成滚动容器内的 `sticky top-0`**：那种放法要靠 `z-10` 与实心底色去躲 diff2html 的行号列（它是 `position: absolute`、`Patch` 的宿主 div 又带着 `relative`，两者都排在横杠之后，而定位元素之间 z-index 为 auto 时按 DOM 顺序绘制——漏了 `z-10` 时横杠确实粘住了，只是整条被滚上来的代码盖在底下，页面上看着就像它压根没粘），横向那半条还要再拆一层（见下面「文件视图」）；排在滚动容器之外时那几个盒子被容器的 `overflow` 裁掉，够不着横杠，两半机制一起消失。**钉住的只有这条横杠**：重命名标注跟着补丁一起滚，它说的是这份补丁的来历，不是「我在看哪个文件」。**外壳那两层由 `DiffView` 导出的 `Panel` 给，两个视图共用**（同 `Notice` / 路径横杠本身）：类名各写一份时漂开的症状是「其中一个面板底下那半屏不跟着滚」，不报错。
- **判「干净」读的是 `repoState`，不是「有没有选过文件」**：第一份 state 还没到（`null`）时走「还没选」那句——左栏此时写的正是 `Loading…`，两栏说的是同一件事。

## 文件浏览器

**`Files` 那一档是仓库目录树，按目录懒加载**：展开一个目录才去取它那一层。数据与判据在 [`git.md`](git.md) 的「目录树的两条 `ls-files`」，本节只管展示。

- **一行 = 缩进 + 展开三角（目录）或等宽占位（文件）+ 名字。** 占位不能省：少了它文件名会比同层的目录名往左挪一截，同一层看着像两层。缩进用**内联 `padding-left`** 按层级算，不生成 depth 个工具类——层数没有上界，而 Tailwind 只产出源码里出现过的类名。
- **状态染色复用变更列表那张 `CODE_COLORS`**（从 `ChangeList.tsx` 导出，不复制）：树上一个文件是不是改过、改成什么样，与左边那份列表说的必须是同一个颜色。判据是拿 `repoState.files` 建一张 `path → 条目` 的表，**冲突条目优先按冲突色**——它两侧状态位都不是 `.`，挑哪一位都会说错一半。
- **被忽略的文件灰显**（次要色 + 降透明度），与 VS Code 一致；**不做「显示/隐藏被忽略」的开关**——它换来的只是一个多数人只会拨一次的按钮，而灰显本身已经把「这不是你的代码」说清楚了。
- 整行挂 `title={entry.path}`：名字会被 320px 裁掉，完整路径在树上找不回来（与变更列表同理，也同样不挂在被裁的那一段上）。
- **展开态与树的缓存活在组件树之外**（`state/tree.ts`）：SSE 刷新要在不丢展开态与滚动位置的前提下换数据，与列表那条约束同源。刷新时**只重取「根 + 当前展开着的、且真的取过的那几层」**，不整棵重来——少了后半条，从没点开过 `Files` 的会话每收到一个 `change` 都要白跑一趟 `ls-files`，而 agent 跑动期间这些事件是密集的。**这条收窄不欠债，因为 `loadDir` 每次调用都真的去取**：收起期间那一层不在刷新范围里、缓存停在收起那一刻，而再展开时 `toggleDir` 自己会取一份新的。若把「缓存里有就不发」当成 `loadDir` 的默认，这笔账就以「展开后少几行」的形式还——页面上是一份陈旧的目录，一直旧到下一个 `change` 到达，不报错、也不空白。手上那份仍然照画，新的回来再换掉。于是 `force` 只剩一个意思：**连「已经在飞」也要再发一趟**，那是刷新专用的（「已经在取就不取」会把一次 `change` 引出的刷新整个丢掉）；展开不传它，连点两下或撞上一次刷新时后一趟自己搭车。**根那一层同样是切到这一档才取**，不在挂载时预取：冷启动预算上因此看不见它；「取过就不再取」只有取根这一处需要，判据因此写在 `App` 那个 effect 里——少了它，切一次 tab 就是取根与刷新各发一趟。
- **树上的选中态与变更列表的选中态是两份**：同一个文件从两处点进去看到的是两样东西（补丁 / 全文），共用一份就得再补一条「这次是从哪点进来的」，那与 `activePane` 是同一个信息的两处实现。

- **树上方另起一条工具栏，眼下只有「全部折叠」一枚按钮**（`Collapse all`，位置对应 VS Code Explorer 的 view actions）。它与上面否决掉的「显示/隐藏被忽略」开关**不是一类东西**：那个是多数人只会拨一次的偏好，而这是每次翻完树都会用一次的一次性动作，替代的是「沿着来路把每个三角逐个点回去」——点数等于展开过的层数。
  - **不塞进 tab 那一行的右端**（那一行右侧本来就空着）：它是 `role="tablist"`，里面躺一个非 tab 元素时读屏会把它当成第三个 tab 报出来。
  - **这条栏排在滚动容器之外**——两个 tab 共用的是那一个 `<nav>`，塞进去按钮会跟着树滚走，不报错，只是往下翻两屏就再也找不着它。排在错误条之下，上面那条「错误条在顶栏之下、列表之上」照旧成立；**只在 `Files` 那一档画**，`Changes` 档下它一个动作都放不了，留一条空栏比不留更费解。
  - **不给这条栏自己的 `border-b`**：tab 行那条已经把它与上面分开，再切一条只是把 320px 的侧栏横着剁得更碎。
  - **横向内边距与顶栏同一档（`px-3`）**：这枚按钮与顶栏那个主题开关是同一个 `IconButton`，于是外层 padding 一致时两枚图标恰好落在同一条竖线上。差几个像素不报错，只是「看着没对齐」，而侧栏右边这一列此刻正好只有它们两个——`app.test.tsx` 拿两处外层的类名钉住这件事（happy-dom 没有排版引擎，能断言的只有类名在不在），故不进红线。
  - **只清展开态、不清 `treeCache`**（机制在 `state/tree.ts` 的 `collapseAll`），与单个目录收起那一半逐字同一条：再展开时不该又空一拍。
  - **一个目录都没展开时照常可点**：那一下写的是一个空集，而每行那份 computed 是记忆化的（空集换空集重算出同一个 `false`），一行都不会重画——是真的无操作，`collapseAll` 因此也不必自己短路。为一个灰掉的图标让这枚按钮订阅 `expandedDirs`、跟着每次展开收起重画不划算，而按钮忽有忽无比常亮更难扫。
  - **不动右侧面板**，与「切 tab 不动右侧」同一条：折的是左栏在列什么，不是用户此刻在读什么——选中的文件躺在被折起来的那一层里也照旧留着。

## 文件视图

**右侧那一份是只读全文，不是 diff。** `FilePayload` 四个 `kind` 全部在 `FileView` 分支，提示行的外观与 `DiffView` 共用同一个 `Notice`。

- **语言判定是「扩展名 → hljs 语言名」的一张小表，且必须先 `getLanguage()` 探一下**：`highlight()` 传未注册的语言名会抛，而这里没有 diff2html 兜底——抛出去炸的是整个文件视图。取不到一律退回 `plaintext`（它已在那 22 个模块里注册着，见 [`diff-render.md`](diff-render.md)）。
- **容器上不得加 `hljs` 类**，理由在 [`style.md`](style.md) 的「文件视图与 `.hljs`」：那条规则是 unlayered 的，会压过 Tailwind 的背景工具类。15 条 token 规则（`.hljs-keyword` 之类）是独立选择器，不挂容器类照样生效。
- **行号做成兄弟元素，不按行切高亮输出**：hljs 的 span 会跨行，切开要自己重开标签——那正是红线在 diff2html 上明令禁止的事，在这里同样不做。行号槽 `sticky left-0`，横向滚代码时它留在左边。
- **`sticky left-0` 要成立，正文那一层必须是 `w-max`。** 长行把正文撑得比面板宽，而横向滚动发生在标题栏底下那层滚动容器上；这一层若是普通块盒，它只有面板那么宽，行号槽因此**一点滑动余量都没有**——粘不粘都是同一个位置，横向一滚整列行号跟着内容滑出视口，而「`sticky left-0`」这几个字还在原地，看上去像是已经处理过了。**从前与它并写的 `min-w-full` 已经去掉**：那半条挡的是「短文件下标题栏缩成半截」，而标题栏搬出滚动区之后宽度不再来自这一层，正文这一路自己没有任何要铺满面板的底色或边框。
- **但这个类只能给正文那一路**，判据是 `NEEDS_WIDE_BOX` 那张按 `kind` 穷举的表（写成 `payload.kind === 'text'` 一句时它就是第二处独立判定 kind 的地方，与 `Payload` 的 switch 各写各的，加进第五个 kind 时漏改这边会让粘性静默退回 static；`Record` 的键是穷举的，漏一个是编译错误）。**理由**：`max-content` 下文本一律不折行，而提示行那几路是散文——整句排成一行横着跑出面板，要横向滚才看得全；symlink 那句里为长路径写的 `break-all` 也救不了，它只把 min-content 降到一个字符、max-content 仍是整句不断。实测读数见 [`../decisions.md` 的「前端渲染与体积」](../decisions.md#前端渲染与体积)。上面这几件事都有断言（`file-view.test.tsx` 直接钉类名——happy-dom 没有排版引擎，能断言的只有类名在不在），故不进红线。
- **标题栏不参与横向滚动，`px-4` 因此就写在 `<h2>` 上。** 它排在滚动容器之外（见上面「选中态与右侧面板」），横杠自己恒等于面板宽，底色与下边框天然铺满。**从前在滚动区里时这条要拆成两个盒子**：底色与下边框归 `<h2>`、`sticky left-0` 与 `px-4` 归里面那个 `inline-block` 的 span，而内边距一旦留在 `<h2>` 上就得改写成 `left-4` 去抵消它，那两个数字从此必须一直相等，改其中一个时没有任何东西会提醒另一个。
- 空态与 diff 那侧共用一句 `Select a file on the left.`：两个 tab 下指的都是左栏，而左栏此刻列的是什么由用户自己看得见。

## 主题开关

**顶栏那个按钮是三档循环：跟随系统 → 亮 → 暗 → 跟随系统。** 默认档是跟随系统，即加开关之前的全部行为；显式选过的档记在 `localStorage`，跨会话保持。为什么是三档而不是两档、为什么不做多标签页同步，见 [`../decisions.md` 的「前端渲染与体积」](../decisions.md#前端渲染与体积)。CSS 那侧的机制（三条 `color-scheme` 规则 + `light-dark()`）在 [`style.md`](style.md) 的「明暗切换」，本节只管状态与控件。

- **「跟随系统」是属性不存在，不是 `data-theme="system"`**：缺省即跟随，于是 CSS 那侧不必为它写第三条规则，`localStorage` 那侧存的也只有两个合法值。
- 接线在 `state/theme.ts`，形状照 `state/title.ts`：一个模块级 signal + 一个 `effect` 把它接到 `document.documentElement` 上，导出一个取消订阅函数由 `main.tsx` 调。**同一个 effect 顺带写 `localStorage`**——属性与持久化是同一次状态变更的两半，拆开就会出现「切了但没记住」这种只在刷新后才看得见的状态。
- **`localStorage` 的读与写各自 `try/catch`**：Safari 隐私模式下光是取值就会抛。抛了就只在内存里生效——按钮照常能点，只是刷新后回到跟随系统。读到不在两个合法值里的脏值同样退回跟随系统，不做修复也不清除。
- **这是仓库里第一份跨会话的用户偏好**，key 为 `difftab:theme`。加第二份之前先想清楚它是不是也该有这一节。
- **`main.tsx` 里在 `render()` 之前接线**，让属性尽早落到 `<html>` 上。但**首帧仍可能闪一下系统色**：CSP 是 `script-src 'self'`（见 [`server.md`](server.md)），页面里塞不了那段惯用的 pre-paint 内联脚本。代价只落在显式选过档、且选的与系统相反的人身上，闪的是一帧底色——为它开 `unsafe-inline` 或维护一份脚本 hash 不划算。
- 控件是图标按钮，`title` 与 `aria-label` 三档分别是 `Follow system` / `Light` / `Dark`。**只画图标不写字**：320px 的顶栏里那三个词会跟项目名抢宽度，而抢输的那个是项目名。三个图形取自 **Lucide**（`Monitor` / `Sun` / `Moon`，ISC），与界面上其余三枚同一套；包只进 `devDependencies`、由构建期 tree-shake，「后端零依赖、前端只装构建期依赖」那条不受影响。颜色不在这里写：lucide 的 stroke 默认就是 `currentColor`，而按钮自己的文字色由 token 给，于是图标跟着深浅翻。

## 页面标题

**浏览器标签页标题是 `<仓库名> · difftab`。** 仓库名取自 `RepoState.repoName`，即工作区根目录名——linked worktree 下那是该 worktree 的目录名，正好把同一仓库的多个工作区分开。

- **仓库名排在产品名之前**：判据是标签被压窄时从**尾部**截断，产品名在前时一排标签压窄后长得一模一样，分辨不出哪个标签属于哪个项目。
- 取不到仓库名时（第一份 state 还没到、或 `repoName` 是空串）退回纯 `difftab`，不画占位符——占位符在那两秒里给的是一段假仓库名，而少一段不是。
- **仓库名是用户数据，不是界面文案**，因此不受「一律英文」的约束：中文目录名会原样出现在标题里。这与 CJK 门禁不冲突——它查的是产物文件的字面量，而仓库名是运行时才有的值，一个字节都不落在产物里。
- 接线在 `web/state/title.ts`：一个 signals `effect` 把 `repoState` 接到 `document.title` 上，**标题格式与接线同住一处**。不放进组件：标题不是组件树的产出，挂在 `App` 的 `useEffect` 上等于让一个 document 级副作用跟着某个组件的生命周期走。`index.html` 里的 `<title>difftab</title>` 保留为 JS 跑起来之前的兜底。**`PRODUCT_NAME` 由本文件导出给顶栏共用**——顶栏的兜底与这里逐字同一串，各写一份的症状是改了其中一处之后两个表面互相说着不同的名字。
