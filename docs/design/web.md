# 前端：界面文案、页面骨架与变更列表

> **TypeScript + Preact + @preact/signals，经 Vite 构建为静态产物**，由后端直接托管。本文件管左栏与页面骨架；右侧面板（编辑器标签页、diff / 文件两个视图的外壳、文件视图）在 [`editors.md`](editors.md)，diff 怎么渲染在 [`diff-render.md`](diff-render.md)，配色与层叠隔离在 [`style.md`](style.md)。选型与被排除的做法见 [`../decisions.md` 的「前端渲染与体积」](../decisions.md#前端渲染与体积)，门禁见 [`../gates.md`](../gates.md)。

## 界面文案与术语

**界面文案一律英文，`<html lang>` 为 `en`。** 判据是**产品表面与文档分属两个读者**：`docs/` 与代码注释写给维护者，中文；而分发形态是 npm 全局包，CLI 的 `--help`、退出提示、版本守卫报错本来就是英文，界面是同一个表面上唯一说中文的部分。中文读者由 `README.zh-CN.md` 承接。首版不做语言切换。

- 术语跟 git 自己的用词走（`Staged` / `Unstaged` / `Untracked` / `Conflicted` / `Detached HEAD` / `Rebasing`），不自造同义词——用户是拿它对照 `git status` 看的。
- **判据是「`dist/web/` 三个产物里的 CJK 字符数为 0」**，不是逐个文件翻源码：漏网的最可能形态是**不长在 JSX 上的那几条**（`state/store.ts` 的错误文案就这么漏过一次），而按文件翻依赖「想不想得起来」。前端产物里本来就不该有中文——注释在构建期已去掉，diff2html / hljs 也不带。
- **后端产物用不了这个判据**：`dist/server/main.js` 不压缩不混淆，中文注释原样留着正是为了可审计。那一侧的用户可见文案是 `sendError` 与各 `*Error` 的字面量，归 `test/unit/server/`。
- 改文案要同步改 `test/unit/web/` 里的可见文本断言。这一条**会报错**，不进红线。
- **句点只跟句子走**：独立的短片段——空态、占位、标签（`No changes` / `Working tree clean` / `Select a file on the left` / `Empty` / `Loading…`）——末尾不加句点，照 VS Code 与 GitHub 的惯例；说明性的完整句子（`Binary file — contents are not compared.`、`File too large to show (…).`）才加。判据是「它是一个标签还是一句话」，不是长短。
- **出错提示分两段：引导句（`Could not load this file`）与原因逐字各占一行，不拼成一句**——原因的来处不止一个（后端 `sendError` 的小写片段、浏览器自己的 `TypeError: Failed to fetch`、500 转发来的 `ENOENT: …`），大小写与句点各成一派，接在冒号后总有一种读起来像两句话撞在一起，而前端管不到那几个来处。反过来把前端兜底改成小写片段也不行：同一条消息在左栏错误条与目录树里是裸着显示的，那里小写开头是退步。
- **too-large 提示的主语随视图走**：diff 视图说 `Diff too large to show (file is 3.0 MB).`，文件视图说 `File too large to show (3.0 MB).`——diff 那侧 5MB 卡的是补丁字节，`size` 却是文件体积，两边都说「File too large」时同一个文件会在 Files 档里照常显示、在 diff 里说太大。行数那一路括号里仍是体积（payload 没有行数），写成 `(3.0 MB)` 而不是 `(3.0 MB in total)`——「in total」暗示前面有分项可汇总。文案在 `tooLargeNotice` 里只写一次，两个视图共用。

## 页面骨架

**外壳是行向 flex：左栏一列（顶栏 → 错误条 → 变更列表 → 状态条），右边是编辑器面板（标签栏 + 一个视图，见 [`editors.md`](editors.md)），面板自屏幕顶端满高到底。** 顶栏不横跨全屏——它归左栏。

- **顶栏里是品牌符号 + 项目名 + 主题开关**，三样而已。**高度显式钉 `h-9`（36px），不写纵向内边距、靠 `items-center` 居中**：右侧编辑器标签栏钉的是同一个值，两条底边于是落在同一条水平线上（`app.test.tsx` 拿两处的 `h-*` 类名互相钉住——漂开时不报错，只是「看着不齐」）。符号排在最左、16px、`aria-hidden`（名字由标签页标题给），是「品牌标识」那一节里那枚 `DifftabMark`，走 `Icon` 外壳、`shrink-0`——被裁的永远是名字。项目名是 `RepoState.repoName`（工作区根目录名，与标签页标题里的是同一份），位置对应 VS Code 侧栏顶端那行文件夹名：这一栏要回答的是「我在看哪个项目」，产品名答不了，而它在标签页标题里仍留着一份。拿不到仓库名时退回纯 `difftab`（**共用的是 `PRODUCT_NAME` 那一串，判据两边各写一次**——两处的组合本就不同，理由在 `state/title.ts`）：「第一份 state 还没到」与「根目录没有 basename」在这里同样合成一种情况。
- **`truncate` 必须落在装项目名的那个 `span` 上，不是顶栏本身**：产品名长度恒定，目录名可以任意长，不裁时被撑开的不是顶栏而是文字自己——不带断点的长名漫过右边框压到 diff 面板上，带连字符的则折成第二行把顶栏撑高。顶栏成为 flex 容器之后**这条得再钉一遍**：`truncate` 留在容器上不起作用（子项的自动最小尺寸会把它撑开），症状与从前一模一样，而 `truncate` 字样还在原地，看上去像是已经处理过了。开关那侧 `shrink-0`，被裁的永远是名字不是按钮。
- **分支状态与监听标注放在左栏底部的状态条**上（位置对应 VS Code 的 status bar）：三样挤进同一行时，320px 减去项目名与间距只剩不到 180px，而收缩优先级由既有机制定死——徽章 `shrink-0`、分支名 `min-w-0` + `truncate`，于是先被裁掉的恰恰是分支名，而它正是这一段存在的理由。沉到状态条后它独占一行。
- **顶栏之下是一行两个 tab（`Changes` / `Files`）**，排在错误条之上。位置对应 VS Code 的 activity bar，**画成两枚紧挨着靠左的图标、但仍是横排一行，不切一列竖排**：竖排要再占一列宽，而 320px 的侧栏里那一列是从文件名身上扣的，两个视图也用不着一整列。两枚按钮各按自身宽度排、不平分整栏——通栏那条细线是行自己的 `divider-b`，选中下划线只是画在它上面的一小段，平分时那一段有半栏宽，看着不像指示器像第二条分隔线。**这一行本身不是那个 tablist**：`role="tablist"` 收在里面只装两枚 tab 的那个 div 上，行的右端按当前档各站一枚按钮：`Changes` 下是列表 / 树的视图切换（见下面「变更列表」的「列表与树两种版式」），`Files` 下是 `Collapse all`（它为什么塞得进见下面「文件浏览器」）；两枚互斥出现、走同一个 `IconButton`，于是位置与外观构造上就相等。外层这一行的类名串因此有三条判据：**通栏那条线归它**（留在 tablist 上时那条线只有两枚 tab 那么宽）；**不给纵向内边距**——tab 的 `border-b` 要落在行的最后 1px 上才盖得住那条线，中间垫上 padding 就错开成双线了；**右内边距是 `pr-3` 不是 `px-3`**，tab 得贴着左边缘起排，而要对齐的本来也只有右边那 12px——那枚按钮与顶栏那个主题开关是同一个 `IconButton`，右 gutter 一致时两枚图标恰好落在同一条竖线上（差几个像素不报错，只是「看着没对齐」，`app.test.tsx` 拿两处的类名钉住它）。**「画在它上面」要靠通栏那条线是 inset 阴影（`divider-b`）而不是 `border-b` 才成立**：容器的 border 画在自己 padding box 之外，tab 的 `border-b` 够不着它，两条边上下相邻，选中那一段就是双线、比未选中处厚一倍；inset 阴影画在 padding box 内侧的最后 1px、背景之上内容之下，tab 那条边正好盖住它。这套机制与右侧编辑器标签栏共用（它为什么必须这样见 [`editors.md`](editors.md)），全仓库只此一种。**那条短线用前景色**（照 VS Code 经典 Dark+ 的 activity bar 活动边框），不用 `focus-border`：后者是「键盘焦点在这里」的颜色，而这一行的 focus-visible 轮廓正用着它，同色时两件事在页面上化成同一种蓝。默认档是 `Changes`——工具存在的理由仍是「瞥一眼改了什么」，目录树是顺带能做到的第二件事。两个视图**共用中间那一层滚动容器**，不各开一个。
- **`Changes` 那枚图标与状态条上分支名前的是同一枚**（Lucide `GitBranch`，对应 VS Code activity bar 上的 Source Control）。**「同一枚」由编译器保证**：两处 import 同一个具名组件，拼错标识符是编译错误——这比从前共用一条导出的 path 字符串强，那种做法里两份漂开时同一个概念在页面上就是两个图形，没有任何东西会响。**`<svg>` 那层外壳走共用的 `Icon`**（理由与 `Badge` 一字不差：`size` 与 `aria-hidden` 在六处各写一遍，漏掉一处不报错、也不画错，只是那一枚比旁边的大一圈，或者被读屏多读一遍）。`Files` 那枚是 `Folder`。
- **只画图标就意味着名字只能由 `aria-label` 给**（`title` 再给一份 tooltip），与顶栏那个主题开关同一条约束：掉了它读屏里就是两个无名控件，而页面上什么都看不出来。`app.test.tsx` 直接钉着这两个名字，故不进红线。
- **切 tab 不动右侧面板（`activeEditor`）**：换的是侧栏在列什么，不是「用户此刻在读什么」——VS Code 里换侧栏视图同样不会换掉编辑器。写成「切到 Files 就清空右侧」时页面看着完全正常，只是每瞄一眼目录树就丢掉正在读的那份 diff。
- **错误条也在左栏内**，排在顶栏之下、列表之上：它说的是「变更列表取不到」，与列表那句兜底文案「原因写在上面了」相邻才成立；横跨全屏则会在 diff 面板顶上再切一条与 diff 无关的横杠。
- **状态条随第一份 state 一起出现**，拿不到时整条不画——与「不先画一个假分支再换掉」同一条取向。
- **分支名前面画一枚分支图标**（位置对应 VS Code status bar 最左那枚）。图形取自 **Lucide 的 `GitBranch`**（ISC），与主题开关那三枚同一套。**detached 与取不到名字时照画**——它标的是「这一栏说的是 HEAD 在哪」，那句话在三种情况下都成立，而按情况藏掉只会让状态条的左边缘忽进忽出。两个类名各挡一件只是「看着不对」的事：`shrink-0` 让 320px 里先被裁的仍是分支名；`self-center` 是因为那一行是 `items-baseline`，而替换元素的基线是它的底边——不写时图标整个坐在文字基线上，比文字高出小半个字。**两个类名都有断言**（`branch-status.test.tsx` 直接钉类名——happy-dom 没有排版引擎，能断言的只有类名在不在），故不进红线。
- **与上游的差距排成 `<behind>↓ <ahead>↑`**：behind 在前、数字在箭头前，逐字照 VS Code status bar 的 `syncLabel`（`${behind}↓ ${ahead}↑`）——这一栏存在的意义就是拿去与另一个窗口对照，两边的两个数一左一右反过来，每看一眼都要在心里翻一次。**两个 0 仍都画出来**（VS Code 在都为 0 时只留一个同步图标，这一半不跟）：「已同步」与「无上游」在页面上必须是两个样子，而无上游根本不输出 `# branch.ab`。顺序**有断言**——`branch-status.test.tsx` 拿两个不同的数一次钉住顺序与写法，故不进红线。
- **滚动的是变更列表那一层（`min-h-0 flex-1 overflow-auto`），不是左栏本身**：顶栏、错误条、状态条都 `shrink-0` 钉在原处，只有列表滚。左右两栏仍各有一个**独立的滚动容器**（右侧那个在标签栏之下，见 [`editors.md`](editors.md)）——SSE 刷新要留住列表的滚动位置，共用一个就做不到。**列表那层必须归零自己的自动最小尺寸**（`min-h-0` 与 `overflow-auto` 各自都够，因为自动最小尺寸只在该轴 `overflow: visible` 时才解析成 min-content）：两个都没有时不报错，只是列表把整列撑高、状态条被挤出屏幕底部。
- **本节不改变 `outputFormat` 的判据**：那条量的是 diff 面板自身的 border box（见 [`diff-render.md`](diff-render.md) 的「版式按面板宽度自动切」），与左栏里放了什么、分成几段都无关。

## 变更列表

**一行的构成是「文件名 → 目录 →（重命名标注）→ 状态位」。** 目录跟在文件名之后、小一号、次要色、**不带尾部斜杠**——它是独立的一段而不是与文件名连读的路径前缀。状态位排在**行尾、`ml-auto` 靠右**，成为侧栏右端的一列定宽字母（位置对应 VS Code Source Control 面板的 decoration）。判据是**侧栏宽度固定 320px 而 `truncate` 从右边裁**：路径在前时先被裁掉的恰恰是文件名，而文件名才是用来认出这一行的东西。故空间不足时**先牺牲目录、保住文件名**（排法参照 VS Code 的 Source Control 面板）。

- **两段必须同住一个 `truncate` span**（名在前、目录作为它的行内子元素）。拆成两个平级 flex 子项**两件事一起坏、且都不报错**：
  - `overflow:hidden` 让每段各自成为 scroll container，基线改按**边框盒**合成而不再露出文字基线，`items-baseline` 于是把两段按底边对齐，字号不同时看着就是没对齐；
  - 谁先被裁只能靠 flex-basis 去调，而给目录 `flex-1` 会把它后面那段重命名标注推到侧栏最右、与它注解的文件名断开。

  同住一个 span 时两件都不必处理：两段共用一个行盒（基线是真的），而省略号在右端**天然**先吃掉排在后面的目录。（`min-w-0` 不在此列——截断盒无论一个还是两个都得给。）
- **这条规则钉的是树的形状，不是版式，所以它有断言**：`change-list.test.tsx` 的「同住一个 truncate span」一条查目录段所在的截断盒是否同时装着文件名，拆成兄弟即红。happy-dom 判不了的只剩「谁先被裁」那半条，归人工。
- 目录被裁是设计中的常态，故**整行挂 `title={file.path}`** 补一份完整路径；不挂在目录那个 span 上——它被裁到零宽时就没得可悬停了。
- **不做文件类型图标**：要么引一套 SVG 资源去顶产物体积门禁，要么自己维护一张扩展名→颜色表，而换来的只是观感。状态位在**行尾靠右**成一列定宽字母（`w-5 text-center shrink-0`，冲突行的 XY 两位也印在那里）：行首不再有东西挡在文件名前面，文件名与树视图里同层目录名的起点齐平；两个截断盒收缩时它 `shrink-0` 不动，长路径行也不会把状态位挤掉。外壳（`ml-auto w-5 shrink-0 opacity-75`）三枚记号共用 `STATUS_SLOT` 一个常量——各写一份时不一致不报错，只是冲突组那一列的字母比别的组横着挪一截。**记号取 0.75 不透明度**，照 VS Code 行尾那枚 decoration 字母（`.monaco-icon-label::after`）那档：颜色 token 与 `gitDecoration.*` 逐字相同，但那里的字母本就比染色的文件名淡一档，画成满色时记号看着比编辑器里重；`Files` 档里染色的文件名仍是满色。**淡一档必须走 `opacity`，不能走 token 的 `/75` 修饰符**——双值 token 经 `color-mix()` 会让整条声明作废（红线里那条）。

- **列表区的三句占位（`Loading…`、「取不到列表」、`No changes`）共用 `SidebarPlaceholder`，居中画在列表区正中**，与右侧面板的空态同一个道理：空着时没有别的东西可对齐，一行贴在左上角的小字看着像漏画了什么。**三句一起居中而不是只居中干净那句**：它们轮流占同一个 `<nav>`，各摆各的位置时干净仓库一启动就是「Loading…」贴左上、几百毫秒后跳到正中——不报错，只是每次启动闪一下。**`h-full` 是居中成立的前提**：`<nav>`（`min-h-0 flex-1 overflow-auto`）是普通块盒不是 flex，不撑满时 `items-center` 只在自己那一行的高度里居中——页面上仍然贴顶、不报错（`change-list.test.tsx` 钉类名）。**不配图标**：320px 的侧栏里那枚会比一行字更抢，而右侧面板同一时刻已经画着一个 ✓。**不与右侧那块合成一个带可选 `icon` 的组件**：那又是一个不填也不报错的开关，且合成后它得同时带两种撑满手段（`h-full` / `flex-1`），看不出自己在哪种宿主里。
- **左栏所有「行」一律 24px，行高由列表区那个 `<nav>` 的 `text-sm/6` 给、底下全靠继承，行自己不写字号也不给纵向内边距**（行是 `<button>`，preflight 的 `font: inherit` 让它连 line-height 一起继承；`Files` 那档的 `Loading…` / `Empty` 占位与 `SidebarPlaceholder` 同样只继承）。判据是一行里嵌着小一号的东西——目录段、状态字母、重命名标注都是 `text-xs`：行高由 line-height 定时它们共用同一个 24px 行盒，靠 `py-*` 凑时各段自带 16 / 20 两种行高、基线要另行对齐，而从前两个视图正是这样各凑各的（`py-1` 对 `py-0.5`），切一次 tab 同一个文件行从 28px 跳到 24px。给在容器上而不是逐行写：「所有行 24px」于是是一条属性，不是每个元素各抄一遍的约定（`app.test.tsx` 钉 `<nav>` 的类名）。**分组标题是唯一的例外**：它自己写 `text-xs`，而 Tailwind 的 `text-*` 会把 line-height 一并重设（`--tw-leading` 不继承），得自带 `/6`——同理 `leading-6` 写在容器上对任何自带 `text-*` 的后代都无效。24px 取自 JetBrains New UI 与 Zed 的树行；VS Code 是 22px，但 Tailwind 预设里没有 13px / 22px 这一档，不为 2px 另加 token。**两棵树的行骨架（flex、通宽、`gap-1.5`、`pr-3`、焦点环）只在 `tree-row.tsx` 的 `ROW_BASE` 一份**，与缩进量、三角、占位同住：各写一份时改其中一处不报错，只是切一次 tab 三角与名字的间距跳一截（`change-list.test.tsx` 与 `file-tree.test.tsx` 各钉一行的类名含 `ROW_BASE`）。对齐方式不在骨架里——文件行是两段文字按基线排，目录行是一枚 SVG 加一段文字得 `items-center`，各补自己那一个；**左内边距三种视图都由 `indent()` 给，平铺列表取第 0 层**（= 12px），不另贴一个会被内联 style 盖掉的 `pl-*`。

### 列表与树两种版式

**tab 行右端那枚开关在平铺列表与目录树之间切换，默认列表。** 位置对应 VS Code Source Control 面板的 View as Tree / View as List：agent 单次改 300+ 文件时目录段满屏重复，按目录扫不出「改动集中在哪」，而树把同一目录下的文件收在一起。**开关的图标与文案表达的是目标视图**（列表下画 `ListTree` + `View as tree`，树下画 `List` + `View as list`），照 VS Code 的惯例——它是一个动作按钮，不是显示当前档的状态灯（顶栏那个三档主题开关显示的是当前档，两者不同类）。只在 `Changes` 档画，与 `Files` 档那枚 `Collapse all` 互斥出现。

- **版式只活在本次页面里，不进 `localStorage`**。判据不是「偏好不值得记」，而是**记了也存不住**：后端 `listen(0)` 每次启动端口随机，`localStorage` 按 origin（含端口）隔离，于是它只能活到同一实例的刷新，换一次 `difftab` 启动就归零——主题那份同样受限，见「主题开关」。为一份跨不了实例的偏好搭一套读写 try/catch 不划算。状态与 `activeTab` 同一形状：一个模块级 signal（`state/change-tree.ts`）。
- **分组标题两种版式都留着**：Conflicted / Staged / Unstaged / Untracked 是 git 语义（XY 两位独立，同一个文件可同时在两组），树只是**组内**的排法。VS Code 同样在每个 group 内各建一棵树。
- **树由 `buildChangeTree(files)` 从路径纯算出来**，每组一份、只在这一组的 `files` 换新时重建。**用 `useMemo` 不用 `useComputed`**：`files` 是 prop 不是 signal，computed 只跟踪 signal，换一份 `files` 它不会重算——页面上就是 SSE 刷新后树停在旧的那份，而列表版式照常在动。建树按 `/` 切路径，每层**目录在前、文件在后**（照 `Files` 那档后端的「目录在前」），各自沿用 git 给的顺序不再排序——多一份排序意见就多一处与 `git status` 不一致的可能。
- **单子目录链紧凑合并**（VS Code 的 compact folders）：一个目录节点**只有一个子节点且它是目录**时合并成一个节点，名字连读成 `src/web/components`、`path` 取链尾。判据是 320px 侧栏里每一层缩进都是从文件名身上扣的，`src` → `web` → `components` 三层各占一行只为放一个文件，文件名反而被挤到最右。有文件的目录不合并——那几个文件就在这一层，合并会让它们看起来属于更深的那层。
- **折叠态记的是 collapsed 集合，不是 expanded 集合**（`collapsedChangeDirs`）：默认全部展开，空集就是「全展开」，SSE 刷新新冒出来的目录不用登记就是展开的。记 expanded 时每个新目录都得在建树时补登记一次，漏了它就默认收起——页面上只是「刚改的那几个文件没显示出来」，而 agent 跑动期间新目录是常态。
- **折叠键带分组 id**（`${groupId}:${path}`）：同一个目录可以同时出现在 Staged 与 Unstaged 两组，两处是两棵子树，折其中一处不该连带折另一处；不带分组时页面看着正常，只是折 Staged 里的 `src` 时 Unstaged 里的也一起没了。合并节点的键取 `path`（链尾）：链被新文件拆开时 `components` 那截保持原状态，新出现的父级默认展开。**陈旧的键不清理**：目录消失又出现时仍是收起的，与 `Files` 那档「收起不丢缓存」同一取向，且清理要在每次 `files` 换新时扫一遍集合。
- **不复用 `state/tree.ts` 的 `expandedDirs`**：那份默认收起、键是仓库路径、且 `refreshTree` 按它发请求——混进去每折一个变更目录就多一趟 `ls-files`，而两棵树本就是两份数据（一份来自 status、一份来自 `ls-files`）。
- **一行的形状与 `Files` 那档同款**：目录行是缩进 + 12px 的 `ChevronRight`（展开 `rotate-90`）+ 名字，带 `aria-expanded`；文件行是缩进 + 等宽占位 + 文件名 + 状态位（靠右），**不再画目录段**（祖先节点已经说了），重命名标注照旧。**行首三样（缩进量、展开三角、与它等宽的占位）与 `Files` 那档共用 `tree-row.tsx` 那一份**：三角按 12 画与占位 `w-3` 是同一个不变量，各写一份时改其中一处不报错，只是另一棵树里文件名比同层的目录名往左挪一截；缩进量各写一个常量同样不报错，只是切一次 tab 缩进跳一截。`FileTree` 已经 import `ChangeList` 的 `CODE_COLORS`，反向 import 会成环，所以这三样独立成文件。状态位与平铺版式同样在行尾靠右——树里每一层的文件行都贴着侧栏右端，缩进只从文件名身上扣。
- **选中态一行不改**：仍是 `activeEditorPath` 按 `path` 比，两种版式下点同一个文件走同一个 `selectFile`（单击预览、双击固定，见 [`editors.md`](editors.md)），切版式不动右侧。
- **本版不做树模式下的 `Collapse all`**：两枚按钮并排是另一次版式改动，等真的有人折过三层再说。

### 行内动作：`Copy path` 与 `Open file`

**悬停一行（或键盘焦点落在行内）时，行尾状态字母之前露出两枚图标按钮：`Copy path` 把仓库相对路径写进剪贴板，`Open file` 以 file tab 打开该文件此刻的全文；点行本身仍是打开 diff。** 位置与触发方式照 VS Code Source Control 的 inline action。两枚各自的理由：看完一份补丁最常见的下一步是把路径贴给 agent 或终端，而此前页面上拿到路径的唯一办法是悬停等 tooltip 再手抄；顺手看一眼整个文件是同一频次的动作，而此前唯一的路是切到 `Files` 沿目录树再找一遍。`Open file` 调的就是目录树那条 `openFile`，但走**固定**档（`{ pinned: true }`）：VS Code 的 `git.openFile` 是 `preview: false`——它是一个明确的「我要这个文件」的动作，不该被下一次单击顶掉；已作为预览 tab 打开时就地固定，否则追加一个固定 tab、现有的预览 tab 不动（机制在 [`editors.md`](editors.md)）。不切侧栏档位（VS Code 从 SCM 开文件同样不切到 Explorer）；按钮不接双击。列表与树两种版式共用 `FileRow`，两边都有；**`Files` 档的文件行只有 `Copy path`**——它点开的本来就是全文。**目录行两棵树都只有 `Copy path`**（复制目录路径：变更树里是合并节点的链尾 `path`，`Files` 里是 `entry.path`）——目录没有 diff 也没有全文可开。为什么不是右键菜单、不复制绝对路径、不弹 toast，见 [`../decisions.md` 的「前端渲染与体积」](../decisions.md#前端渲染与体积)。下面几条都有类名与树形断言（`change-list.test.tsx` / `file-tree.test.tsx`），故不进红线。

- **`Copy path` 复制的是页面上现成的 `path`（仓库相对、`/` 分隔）**，走 `navigator.clipboard.writeText`——服务绑定 `127.0.0.1`，loopback 在三家浏览器里都是 secure context，API 一定在。**反馈画在按钮自己身上**：写成功后图标换 Lucide `Check`、label 换 `Copied`，1.5s 后复原；写失败（reject）静默不换，不画错误——失败只剩用户拒了权限这一种，而一条错误条在 320px 侧栏里没地方落。计时器随组件卸载清掉（SSE 刷新可能在 1.5s 内把这一行换掉）。
- **`Copy path` 排在 `Open file` 左侧**（DOM 顺序即 Tab 键顺序）：`Open file` 留在紧贴状态位的位置不动。两枚之间不加 gap——各自的 `p-0.5` 已隔出 4px，照 VS Code action bar。
- **已删除的文件照画 `Copy path`**（`git checkout -- <path>` 正要这条路径），`Open file` 那半仍按 `isAbsentFromWorktree` 判（下面那条）。于是占位有两档宽：两枚 `w-10`（40px）、一枚 `w-5`；按钮外壳的 `right-9.5` 不随枚数变——它锚在状态位左侧。
- **一行的形状本身是 `tree-row.tsx` 的 `TreeRow`，两棵树四种行都走它**：`<li>` 里一个 group div 装行按钮与行内动作的外壳，子层 `<ul>` 在 div 之外；行按钮的属性原样透传，`badge`（行尾记号）、`actions`（那一两枚按钮）、`sublevel` 各占一个槽。**占位的枚数从 `actions` 算出来**——占位与外壳里真画的枚数各写一份时漂开不报错，只是省略号多退或少退 20px，由同一个组件从同一份列表画两处，这一条就不需要有人记得了。`REVEAL`、`ROW_GROUP` 只为让用例钉住才导出；`CopyPathButton` 也住这里。`FileTree` 已 import `ChangeList`，反向会成环。

- **按钮是行按钮的兄弟，不是孩子**：按钮里不能套按钮，理由与编辑器 tab 上那枚 × 一字不差（见 [`editors.md`](editors.md)）。**行按钮与外壳同住一个 `group relative` 的 `<div>`（`tree-row.tsx` 的 `ROW_GROUP`），`<li>` 本身不是 group**：目录行的 `<li>` 里还套着子 `<ul>`，group 挂在 `<li>` 上时悬停任一后代整段目录行都会亮出按钮、底色也一起变；文件行本可以直接挂在 `<li>` 上，但四种行只留一个形状，两棵树的用例与文档才只需说一遍。行按钮之后并排一个绝对定位的外壳装那一两枚 `IconButton`；它的事件压根不经过行按钮，点它不会顺带开一个 diff tab、也不会折叠目录。
- **显隐走 `display`（`hidden` + `group-hover:flex group-has-focus-visible:flex`），不走透明度**：编辑器 tab 上那枚 × 用透明度是为了留住位置，而这里透明的按钮是一块看不见却能点的死区——点到目录文字的尾巴会误开文件。键盘那半条**是 `has-focus-visible` 不是 `focus-within`**：Tab 从行按钮移过去时它得先显示出来才接得住焦点，这两个都做得到；差别在鼠标——点一下按钮后 Chrome / Firefox 把焦点留在它身上，`:focus-within` 于是一直成立，鼠标移开后按钮还钉在行上，直到点别处把焦点带走；鼠标点出来的焦点不算 focus-visible。不在点击后 `blur()`：键盘用户按 Enter 之后焦点就没了。编辑器 tab 上那枚 × 仍用 `focus-within`——活动 tab 本来就常亮着 ×。**第三条 `pointer-coarse:flex` 给触屏常驻显示**：Tailwind v4 把 `group-hover:*` 包在 `@media (hover: hover)` 里，触屏上那半条从不成立，而触摸来的焦点也不算 focus-visible（iOS Safari 根本不给按钮焦点）——少了它触屏上两枚按钮永远 `display: none`，页面照常，只是从来没人见过它们。
- **出现时文字真的重新排版，靠行按钮里一个与按钮组等宽的占位（一枚 `w-5`、两枚 `w-10`）**：占位与按钮外壳**共用同一个 `REVEAL` 常量**，两处的显隐必须是同一对变体——各写一份时漂开不报错，只是文字被挤开了而按钮没出来（或反过来按钮盖在文字上）。省略号于是在按钮出现时提前 26 / 46px，与 VS Code 一致。**不常驻预留**（每行永久少几十像素文字宽度，320px 的侧栏里是一到两成），**也不覆盖在文字上**（得给按钮补一块与行底色相同的遮罩，遮罩色还随选中态变，覆盖处没有省略号只有一道硬边）。
- **按钮外壳 `right-9.5`（38px）= `ROW_BASE` 的 `pr-3`（12）+ 状态位 `w-5`（20）+ `gap-1.5`（6）**，即紧贴状态位左侧；`IconButton` 是 `p-0.5` + 16px 图标 = 20px，一枚与 `w-5` 的占位等宽、两枚与 `w-10` 等宽。文字被截断的行里占位正好在按钮底下；短行里占位贴着文字、按钮悬在空白上——两种情况按钮都盖不到字，占位保证的只是「文字末端永远在按钮左缘之左」。改行骨架的间距或状态位宽度时这道加法要跟着改，症状只是「按钮与字母挨着或错开几像素」。
- **行的悬停底色画在 group div 上（`ROW_GROUP` 里那条 `hover:`），不画在行按钮上**：指针从行上移到按钮上时已经离开了 `<button>`，底色挂在按钮上那一刻就消失、按钮悬在一块没底色的行上。按钮是 div 唯一的在流子项且通宽，选中行自己的底色照常盖在上面；于是三种行类里都没有悬停底色，加第四种行也不必记得写。group 不含子 `<ul>`，悬停后代不会把祖先目录行一起点亮。
- **工作区里已不存在的文件不画 `Open file`**：它唯一能打开的是一条 `Could not load this file`。VS Code 对已删除条目照样画、点了报错，这里刻意不跟。判据是 `shared/protocol.ts` 的 `isAbsentFromWorktree`（git 知识不进组件）：冲突条目的 XY 是合并阶段码、只有 `DD` 是文件不在（`DU` / `UD` 工作区各留着一方的版本），非冲突看 `unstaged === 'D'` 或 `D.`——**只看 `unstaged === 'D'` 会把 `UD` 误判成不在**。`D.` 那一支是取舍：索引里没有的路径 git 不再比对工作区，`git rm --cached` 后文件其实还在，但非忽略时它另有一条 `?` 记录照常给按钮，只有「`--cached` + 被忽略」这一种组合少一枚（`Files` 档里仍可点开）；对 `D.` 放行则让最常见的 `git rm` 点出一条错误。
- **`Open file` 的图标是 Lucide `FileInput`**（文件轮廓 + 一支从左进入文件的水平箭头），Lucide 里最贴近 codicon `go-to-file` 的一枚——它是一个「跳到这个文件去」的动作。**不用 file tab 那枚 `FileCode`**：那是种类标识，画在动作按钮上读不出「点了会发生什么」，只像行尾多了一枚装饰；`FileSymlink` 是符号链接、`FileOutput` 的箭头朝外（导出），语义各自跑偏。`label` 为 `Open file`，照 `View as tree` / `Collapse all` 的写法；`Copy path` 那枚是 Lucide `Copy`（两张叠着的纸），与 GitHub / VS Code 的复制图标同形。选中行上两枚仍是次要色（`IconButton` 不收 class），深色选中底 `#04395e` 上 `#9d9d9d` 的对比约 4.3:1，够一枚图标用。

## 文件浏览器

**`Files` 那一档是仓库目录树，按目录懒加载**：展开一个目录才去取它那一层。数据与判据在 [`git.md`](git.md) 的「目录树的两条 `ls-files`」，本节只管展示。

- **一行 = 缩进 + 展开三角（目录）或等宽占位（文件）+ 名字 + 行尾的状态记号。** 占位不能省：少了它文件名会比同层的目录名往左挪一截，同一层看着像两层。缩进用**内联 `padding-left`** 按层级算，不生成 depth 个工具类——层数没有上界，而 Tailwind 只产出源码里出现过的类名。行的骨架（间距、焦点环）取 `tree-row.tsx` 的 `ROW_BASE`，与变更列表的树视图同一份；行高不在骨架里，由列表区的 `<nav>` 给——为什么、由谁钉住，写在「变更列表」那一节。
- **状态染色复用变更列表那张 `CODE_COLORS`**（从 `ChangeList.tsx` 导出，不复制）：树上一个文件是不是改过、改成什么样，与左边那份列表说的必须是同一个颜色。判据是拿 `repoState.files` 建一张 `路径 → 状态码` 的表（下一条），**冲突条目优先按冲突色**——它两侧状态位都不是 `.`，挑哪一位都会说错一半。
- **文件行的行尾印状态字母，目录行的行尾印一枚圆点**（位置与配色对应 VS Code Explorer 的 git decoration）。字母那枚**就是变更列表的 `StatusBadge`**（同一个组件，不另画一枚）：靠右成一列、`w-5` 定宽，与 `Changes` 档切过来时同一个位置；三枚记号（字母、冲突两位、圆点）的外壳同取 `STATUS_SLOT` 那一个常量，宽度一致由此成为结构而不是约定；印哪一位与名字染色同一个判据（冲突按 `U`，其余先看工作区侧）。
  - **目录只印圆点、不印字母，但名字与圆点都染色**：一个目录底下可以同时躺着改过的和没改过的文件，给它挑一个字母就是替用户下结论，圆点只说「底下有事」。颜色按后代**归并**：先看有没有冲突（那是用户此刻唯一要处理的东西），再依次 `M`/`T`/`R`/`C` → `D` → `A` → `?`——修改是绝大多数情形，未跟踪是最弱的主张，排在最后；**这是展示上的取舍**，混合目录取哪个都对不了所有人，判据只求稳定。
  - **判据表是 `codeByPath`（`state/store.ts` 里的 computed）**：每个改动条目把自己的状态码记到**自己的路径与所有祖先目录**上，同一个键按上面的优先级归并。一张表同时回答文件行与目录行，`Row` 里不按 `kind` 分支查表——submodule 在树上是一条 `directory`，而它的改动在 status 里记在它自己的路径上（`S.M.`）、不在任何后代，「自己的路径也算一份」正是让它不需要特判的那一条（`file-tree.test.tsx` 有断言）。每行只读自己那一格，别的行的状态变了不重画。**被忽略的目录不会有圆点**——忽略清单里的东西本来就不进 `git status`，这一层什么都不用判。
- **被忽略的文件灰显**（次要色 + 降透明度），与 VS Code 一致；**不做「显示/隐藏被忽略」的开关**——它换来的只是一个多数人只会拨一次的按钮，而灰显本身已经把「这不是你的代码」说清楚了。
- 整行挂 `title={entry.path}`：名字会被 320px 裁掉，完整路径在树上找不回来（与变更列表同理，也同样不挂在被裁的那一段上）。
- **文件行与目录行悬停都露出一枚 `Copy path`**，机制与变更列表那节「行内动作」逐字相同——行走同一个 `TreeRow`。`Open file` 这里不画，点行开的本来就是全文。**没有状态记号的行（没改动的文件、目录）占位落在按钮右侧 26px 处**：外壳锚在 `right-9.5` 不随记号有无变（一列按钮才对得齐），而占位只保证「文字末端在按钮左缘之左」——这条在有没有记号时都成立，只是记号不在时占位底下是空的。
- **展开态与树的缓存活在组件树之外**（`state/tree.ts`）：SSE 刷新要在不丢展开态与滚动位置的前提下换数据，与列表那条约束同源。刷新时**只重取「根 + 当前展开着的、且真的取过的那几层」**，不整棵重来——少了后半条，从没点开过 `Files` 的会话每收到一个 `change` 都要白跑一趟 `ls-files`，而 agent 跑动期间这些事件是密集的。**这条收窄不欠债，因为 `loadDir` 每次调用都真的去取**：收起期间那一层不在刷新范围里、缓存停在收起那一刻，而再展开时 `toggleDir` 自己会取一份新的。若把「缓存里有就不发」当成 `loadDir` 的默认，这笔账就以「展开后少几行」的形式还——页面上是一份陈旧的目录，一直旧到下一个 `change` 到达，不报错、也不空白。手上那份仍然照画，新的回来再换掉。于是 `force` 只剩一个意思：**连「已经在飞」也要再发一趟**，那是刷新专用的（「已经在取就不取」会把一次 `change` 引出的刷新整个丢掉）；展开不传它，连点两下或撞上一次刷新时后一趟自己搭车。**根那一层同样是切到这一档才取**，不在挂载时预取：冷启动预算上因此看不见它；「取过就不再取」只有取根这一处需要，判据因此写在 `App` 那个 effect 里——少了它，切一次 tab 就是取根与刷新各发一趟。
- **树上的选中态与变更列表的选中态是同一份 `activeEditorPath`**（活动 tab 的路径，不看种类；理由在 [`editors.md`](editors.md) 的「编辑器标签页」）。同一个文件从两处点进去看到的仍是两样东西（补丁 / 全文）、在标签栏里仍是两个 tab——那是 tab 的身份，与「左栏哪一行亮」是两件事；高亮只回答「右侧此刻是哪个文件」，两棵树各拿自己的路径去比同一个值。

- **tab 那一行的右端是「全部折叠」一枚按钮**（`Collapse all`，位置对应 VS Code Explorer 的 view actions）。它与上面否决掉的「显示/隐藏被忽略」开关**不是一类东西**：那个是多数人只会拨一次的偏好，而这是每次翻完树都会用一次的一次性动作，替代的是「沿着来路把每个三角逐个点回去」——点数等于展开过的层数。
  - **它必须是 tablist 的兄弟，不是它的孩子**：从前这枚按钮另起一条栏，正是因为「tab 那一行是 `role="tablist"`，里面躺一个非 tab 元素时读屏会把它当成第三个 tab 报出来」。那半条判断成立，但它拦的是 DOM 上的父子关系而不是页面上的位置——把 `role="tablist"` 收进内层那个只装两枚 tab 的 div，按钮站在它旁边，两件事就不冲突了。写成孩子时页面上完全看不出来，只有读屏里多一个无名 tab，故 `app.test.tsx` 直接钉住这层父子关系（同这一节其余那几条类名断言），**不进红线**。
  - **省下的是一整条横栏**：320px 的侧栏本来就在被横着剁，而那条栏里只有右端一枚图标，左边整条是空的；tab 行的右侧原本也空着。**切档不引起版式抖动**：tab 按钮比这枚按钮高（`py-1.5` 对 `p-0.5`），行高由 tab 定，按钮进出时那一行一个像素都不动。
  - **只在 `Files` 那一档画**，`Changes` 档下它一个动作都放不了。**排在滚动容器之外**这条照旧成立且仍钉着——两个 tab 共用的是那一个 `<nav>`，掉进去按钮会跟着树滚走，不报错，只是往下翻两屏就再也找不着它。
  - **它不另起一个组件**：壳里装过的那点版式（对齐、只在哪一档画）全是侧栏那一行的知识，搬空之后剩下的是一个零 prop 的透传壳，两处 import 换一层没有内容的间接——直接写在 `App` 那一行里，「哪枚图标、点了做什么、为什么不做禁用态」就与它的位置同住一处。`state/tree.ts` 的 `collapseAll` 仍是那个动作的唯一实现，树那侧的用例直接调它，不再为点一下而在 `FileTree` 旁边摆一个假侧栏。
  - **只清展开态、不清 `treeCache`**（机制在 `state/tree.ts` 的 `collapseAll`），与单个目录收起那一半逐字同一条：再展开时不该又空一拍。
  - **一个目录都没展开时照常可点**：那一下写的是一个空集，而每行那份 computed 是记忆化的（空集换空集重算出同一个 `false`），一行都不会重画——是真的无操作，`collapseAll` 因此也不必自己短路。为一个灰掉的图标让这枚按钮订阅 `expandedDirs`、跟着每次展开收起重画不划算，而按钮忽有忽无比常亮更难扫。
  - **不动右侧面板（`activeEditor`）**，与「切 tab 不动右侧」同一条：折的是左栏在列什么，不是用户此刻在读什么——选中的文件躺在被折起来的那一层里也照旧留着。

## 主题开关

**顶栏那个按钮是三档循环：跟随系统 → 亮 → 暗 → 跟随系统。** 默认档是跟随系统，即加开关之前的全部行为；显式选过的档记在 `localStorage`，跨会话保持。为什么是三档而不是两档、为什么不做多标签页同步，见 [`../decisions.md` 的「前端渲染与体积」](../decisions.md#前端渲染与体积)。CSS 那侧的机制（三条 `color-scheme` 规则 + `light-dark()`）在 [`style.md`](style.md) 的「明暗切换」，本节只管状态与控件。

- **「跟随系统」是属性不存在，不是 `data-theme="system"`**：缺省即跟随，于是 CSS 那侧不必为它写第三条规则，`localStorage` 那侧存的也只有两个合法值。
- 接线在 `state/theme.ts`，形状照 `state/title.ts`：一个模块级 signal + 一个 `effect` 把它接到 `document.documentElement` 上，导出一个取消订阅函数由 `main.tsx` 调。**同一个 effect 顺带写 `localStorage`**——属性与持久化是同一次状态变更的两半，拆开就会出现「切了但没记住」这种只在刷新后才看得见的状态。
- **`localStorage` 的读与写各自 `try/catch`**：Safari 隐私模式下光是取值就会抛。抛了就只在内存里生效——按钮照常能点，只是刷新后回到跟随系统。读到不在两个合法值里的脏值同样退回跟随系统，不做修复也不清除。
- **这是仓库里第一份跨会话的用户偏好**，key 为 `difftab:theme`。加第二份之前先想清楚它是不是也该有这一节。**但「跨会话」目前只到同一实例的刷新为止**：后端 `listen(0)` 每次启动端口随机，而 `localStorage` 按 origin（含端口）隔离，换一次 `difftab` 启动读到的就是一份空存储。修法记在 [`../history.md`](../history.md) 的「未完事项」；变更列表的版式开关正因为这条不进 `localStorage`。
- **`main.tsx` 里在 `render()` 之前接线**，让属性尽早落到 `<html>` 上。但**首帧仍可能闪一下系统色**：CSP 是 `script-src 'self'`（见 [`server.md`](server.md)），页面里塞不了那段惯用的 pre-paint 内联脚本。代价只落在显式选过档、且选的与系统相反的人身上，闪的是一帧底色——为它开 `unsafe-inline` 或维护一份脚本 hash 不划算。
- 控件是图标按钮，`title` 与 `aria-label` 三档分别是 `Follow system` / `Light` / `Dark`。**只画图标不写字**：320px 的顶栏里那三个词会跟项目名抢宽度，而抢输的那个是项目名。三个图形取自 **Lucide**（`Monitor` / `Sun` / `Moon`，ISC），与界面上其余三枚同一套；包只进 `devDependencies`、由构建期 tree-shake，「后端零依赖、前端只装构建期依赖」那条不受影响。颜色不在这里写：lucide 的 stroke 默认就是 `currentColor`，而按钮自己的文字色由 token 给，于是图标跟着深浅翻。

## 页面标题

**浏览器标签页标题是 `<仓库名> · difftab`。** 仓库名取自 `RepoState.repoName`，即工作区根目录名——linked worktree 下那是该 worktree 的目录名，正好把同一仓库的多个工作区分开。

- **仓库名排在产品名之前**：判据是标签被压窄时从**尾部**截断，产品名在前时一排标签压窄后长得一模一样，分辨不出哪个标签属于哪个项目。
- 取不到仓库名时（第一份 state 还没到、或 `repoName` 是空串）退回纯 `difftab`，不画占位符——占位符在那两秒里给的是一段假仓库名，而少一段不是。
- **仓库名是用户数据，不是界面文案**，因此不受「一律英文」的约束：中文目录名会原样出现在标题里。这与 CJK 门禁不冲突——它查的是产物文件的字面量，而仓库名是运行时才有的值，一个字节都不落在产物里。
- 接线在 `web/state/title.ts`：一个 signals `effect` 把 `repoState` 接到 `document.title` 上，**标题格式与接线同住一处**。不放进组件：标题不是组件树的产出，挂在 `App` 的 `useEffect` 上等于让一个 document 级副作用跟着某个组件的生命周期走。`index.html` 里的 `<title>difftab</title>` 保留为 JS 跑起来之前的兜底。**`PRODUCT_NAME` 由本文件导出给顶栏共用**——顶栏的兜底与这里逐字同一串，各写一份的症状是改了其中一处之后两个表面互相说着不同的名字。

## 品牌标识

**符号是「一段 diff hunk」：三条圆角色条，上下文（灰）、删除（红）、新增（绿），没有外框，没有字标。** 24 网格（与 Lucide 的界面图标同一坐标系），三条各高 4、`rx=1.5`、左缘齐在 `x=4.5`，宽 10 / 15 / 12，包围盒 4.5..19.5 × 4..20、横竖都以 12 为中心——左缘是按包围盒算出来的，不是「代码行从左起」的习惯值，写 3 时整体偏左 1.5 单位。由填充不由描边——16px 下 2 单位描边的线稿糊成一团，色块还是三条。为什么从「标签页里两行」换成这版、颜色为什么固定、字标为什么退役，见 [`../decisions.md` 的「前端渲染与体积」](../decisions.md#前端渲染与体积)。

- **几何只有一份，在 `brand/geometry.mjs`**（纯 JS + 旁边一份 `.d.mts`）：`components/Logo.tsx` 从它拿符号，`scripts/logo.mjs` 从它拼出 `assets/` 下的 SVG 与 `index.html` 里的两条 favicon。写成 `.mjs` 是因为脚本零依赖、import 不了 TS；反过来让组件 import 脚本，等于把一个会拉起 Chrome 的模块打进前端产物。改符号只改这一份再 `node scripts/logo.mjs`——它重写 `assets/*.svg`，找得到 Chrome 时再渲出社交预览 PNG 与 favicon 的 PNG 兜底并回写 `index.html` 两个标记之间的那段。**几何或 token 改了却没重跑，红的是 `test/unit/web/logo.test.ts`**：它拿 `index.html` 里现成的那条 SVG favicon 与脚本此刻会生成的比。
- **红绿是固定的品牌色，明暗两档不切，常量与几何同住 `geometry.mjs`，不进 `app.css`。** 删除 `#e5484d`、新增 `#30a46c`，选的是在纯白与 `#1f1f1f` 上对比都够的中等明度；于是 favicon 的 PNG 兜底、社交预览、README 头图三处的红绿逐字节相同。不用 `--color-git-added` / `--color-git-deleted`：那两个 token 是给文件名文字调的，铺成色块亮档偏泥、暗档偏粉。也不另立 token：`@theme` 里 CSS 没引用的 token 会被 Tailwind 裁掉，而它们在 CSS 里本来就没有引用处——唯一的读者是 `geometry.mjs` 与脚本；放进去只是给 `check:css` 多两个「深浅共用同一取值」的计数。**只有上下文那条跟主题走**：`fill: currentColor` + `fill-opacity: 0.35`，组件里跟着顶栏文字色翻深浅；独立 SVG 文件在根元素写 `color` 并内嵌一条 `@media (prefers-color-scheme: dark)` 在 `--color-editor-foreground` 的两档之间切，脚本生成时用正则从 `app.css` 的 `light-dark()` 里取值，不另抄一份。
- **顶栏那枚由 `lucide-preact` 导出的 `createLucideIcon` 造出来**，于是它与 `GitBranch` 那些是同一个类型、走同一个 `Icon` 外壳，`size` / `aria-hidden` 不必另写一份。**每条 rect 自带 `stroke: 'none'`**——Lucide 把 `stroke="currentColor" stroke-width="2"` 写在 `<svg>` 上给描边图标用，rect 会继承它、被描上一圈 2 单位的边，而这一圈在 16px 下只是「色条比预想的胖、颜色发暗」。三条的 `fill` 也写在各自身上，于是 `iconNode` 就是完整的图形，脚本与测试比对的也是它。
- **没有字标**：界面只用符号；README 头图是 `assets/mark.svg` 与「difftab」同住一个 `<h1>` 横排（图 40px、`align="top"`：GitHub 的 sanitizer 只放行 `align` 不放行 `style`，而 40px 正好是 `h1` 的行高 2em × 1.25，顶对齐即整行填满、色块落在文字正中；`middle` 是把图的中点钉在基线上，图整个沉到文字下方），GitHub 与 npm 页面本就是文字，不需要一张图来写名字；社交预览里的「difftab」与 tagline 走系统 sans 的 `<text>`——那张是 Chrome 截成 PNG 后才定型的，「SVG `<text>` 在 GitHub 的 `<img>` 沙箱里拿不到字体」那条限制不作用于它，而 `mark.svg` 里一个字都没有。**社交预览里符号与名字的间距、整组居中都按符号的可见包围盒（4.5..19.5）量，不按 24 网格**——按网格量时右侧 4.5 单位的留白会叠进间距，40px 就成了 76px，看着只是「空了一截」；包围盒由脚本从 `MARK` 的 rect 算出，不另抄字面量。
- **favicon 是两条 `<link rel="icon">`，都是 data URI，不加静态路由**：`security.ts` 的 CSP 早已放行 `img-src data:`，而加文件意味着 `assets.ts` 白名单与冒烟里的 `WEB_ASSETS` 各补一处。**SVG 那条排在 PNG 之后**——Chrome / Firefox 取文档里靠后的那条合适的（SVG 带媒体查询随明暗切），Safari 不认 SVG favicon、退到 32×32 的 PNG：红绿照常，上下文那条给中灰 `#808080`，两档底色上都看得见。
- **README 头图是 `assets/mark.svg`**，两份 README 同一路径；npm 包页面按 `repository` 字段把相对路径改写到 GitHub raw，同一份 README 两边通用。**GitHub 社交预览没有 API**：`assets/social-preview.png`（1280×640）要手工上传到仓库 Settings → Social preview，改了 logo 就得再传一次。
- **`assets/` 刻意不进 `files`**：它只给 GitHub 与 README 用，进 tarball 是白给用户的几十 KB（`check:pack` 查的是 pack 的实际输出，混进去会红）。
