# difftab — 产品边界

> **一句话定位**：一眼看懂 AI 编码 Agent 改了哪些代码——CLI 启动、本地网页展示，只读查看当前工作区的 diff 与分支状态，冷启动和资源占用做到最轻。
>
> 产品名 difftab = diff + tab，意指一条命令换来一个装着 diff 的浏览器标签页，看完关掉。

## 背景与目标

开发者使用编程 agent 完成开发任务后，需要快速看一眼代码变更了什么、当前分支状态如何。这个诉求本质是「瞥一眼」，不是「审查会话」——只需要在 agent 跑的过程中或跑完之后，随手确认改动内容。**查看当前工作区的 diff 和分支状态是最高频动作**，每次 agent 完成任务后都会用到。

**形态：纯只读，零写操作**。工具在终端敲一条命令启动，自动打开浏览器展示当前仓库的变更，看完关掉标签页即可，进程随后自行退出，不常驻占用资源。

## 目标用户与分发

核心用户：使用 AI coding agent 后需要快速查看当前代码变更的开发者，跨平台（macOS / Windows / Linux）使用。

分发方式：npm 包，`npm i -g difftab` 全局安装（推荐）或 `npx difftab` 直接试用（pnpm 用户为 `pnpm add -g difftab` / `pnpm dlx difftab`）。目标用户使用 AI coding agent，机器上必然已有 Node 环境，无需额外提供免运行时的分发形态。正式支持三端，CI 版本矩阵为 **Node 22 / 24 / 26 × 三平台**，`engines.node` 声明为 `>=22.0.0`。

**本仓库自身用 pnpm 开发，这与用户侧的安装方式无关**——包照常发到 npm registry，且 `dependencies` 为空、零传递依赖，用户用哪个包管理器安装都一样。

## 功能范围

| 功能 | 说明 | 优先级 |
|---|---|---|
| CLI 启动 | 在仓库目录下执行命令，自动识别当前 git 仓库，启动本地服务并打开默认浏览器 | P0 |
| 变更文件列表 | 展示已暂存、未暂存、未跟踪三类变更文件及其状态，纯展示。分组与状态字母照 VS Code Source Control；列表 / 树两种版式；每行悬停露出 `Copy path` 与 `Open file` 两枚行内按钮 | P0 |
| 查看 Diff | 以 `git diff HEAD` 为基准，**按文件懒加载**，diff2html 渲染 + 语法高亮；面板放得下两列时并排、放不下时逐行，标签栏右端可手动切换两种版式（本次页面内固定）。未跟踪文件视为全新增，重命名识别并标注，位图图片新旧两张并排对照；其余二进制文件与过大的文件只给一句提示，不加载卡死 | P0 |
| 当前分支状态 | 展示当前所在分支，以及相对远程的 ahead/behind 计数，纯只读展示 | P0 |
| 分支列表 | 点左栏状态条上的分支名弹出本地分支、远程分支、标签三组（照 VS Code 的分支 quick pick），可按名字过滤。**选中一项即把名字复制进剪贴板**——checkout 属「任何仓库写操作」，用户拿着名字去终端里自己切 | P1 |
| 自动刷新 | 文件系统/仓库状态变化后，通过 SSE 推送前端自动刷新。核心场景是「agent 还在跑、边改边看」，不自动刷新会明显削弱工具价值。监听不可用时降级为轮询并在 UI 标注 | P0 |
| 同仓库单实例 | 启动时检测该仓库路径是否已有实例运行，有则直接打开浏览器指向已有实例，不重复起进程 | P0 |
| 空闲自动退出 | 无任何已连接客户端持续 45 秒后本地服务进程自动退出；同时保留 Ctrl+C 手动退出 | P0 |
| 明暗主题 | 配色仿 VS Code，**默认跟随系统**；顶栏一个开关在「跟随系统 / 亮 / 暗」三档间循环，选择记在浏览器本地（目前只活到同一实例的刷新，见 [`design/web.md`](design/web.md) 的「主题开关」） | P1 |
| 左栏宽度 | 左栏右边缘一条拖拽把手（照 VS Code 的 sash）调宽度，双击复位，键盘可达 | P1 |
| 文件浏览器 | 侧栏 `Files` tab 是仓库目录树，**按目录懒加载**，文件来源是 git 视角：已跟踪 + 未跟踪 + 被忽略的（后者灰显）。点任一文件在右侧只读查看全文，边界情况与 diff 那侧同一套（图片成图、二进制与过大的给提示），符号链接只展示链接目标、不跟随。树跟着右侧活动 tab 展开并定位 | P1 |
| 编辑器标签页 | 右侧面板顶部一条标签栏，可同时挂多个文件，单击预览、双击固定（照 VS Code）；同一路径的 diff 与全文是两个 tab。自动刷新后改动已消失的 diff tab 自动关闭，重命名的跟到新路径。全文 tab 在栏右端有一枚 `Copy file contents`，把整份文件原文写进剪贴板 | P1 |
| Quick Open | 照 VS Code 的 `⌘P` / `Ctrl+P`：弹出 quick pick，按文件名模糊匹配全仓文件（已跟踪 + 未跟踪，不含被忽略的），选中即以固定 tab 只读打开全文。空输入时列当前的变更文件。顶栏另有一枚 `Go to File` 按钮 | P1 |
| 全仓搜索 | 侧栏第三档 `Search`（照 VS Code Search 视图，`⌘⇧F` / `Ctrl+Shift+F` 直达）：按**字面量**搜工作区此刻的内容（已跟踪 + 未跟踪，不含被忽略的与二进制），可选 `Match Case` / `Match Whole Word`，**不做正则**。结果按文件分组、命中段高亮，点一行即打开文件并跳到那一行。档位可见时随自动刷新重搜 | P1 |
| 提交历史 | `Changes` tab 里变更列表下面的 `History` 分区（照 VS Code Source Control 的 Graph），列出 HEAD 可达的近期提交，标出当前分支与上游各指着哪一条，滚到底续页。单击一条原地展开它改了哪些文件，点文件以 tab 只读查看它在这次提交里的 diff。**纯查看**：不 checkout、不 revert、不 cherry-pick；partial clone 里不在本地的内容如实说取不到，**不替用户去远端取**——那会往对象库里写 | P1 |

技术实现见 [`design/`](design/)。

## 明确不做（Non-goals）

分两类：**长期不做**是产品的架构性承诺，破例等于变成另一个产品；**首版不做**是本版范围收窄，后续是否加入以实际使用中暴露的真实痛点为依据，不提前预设。**两类同为硬约束——「首版不做」不等于「可以先做」。**

### 长期不做

- **任何仓库写操作**——不 stage/unstage、不 commit、不 discard、不 pull/push/sync、不创建/切换分支、不 stash。工具全程只读，不需要用户对「工具会不会动我的仓库」有任何顾虑。**这是产品的核心承诺**（作用域见 `AGENTS.md` 第 1 节）
- **代码编辑功能**——不是编辑器，diff 与文件浏览器**都只用于查看**；放开这条会推翻 diff 渲染的整个选型
- **账号体系、云同步**——工具是纯本地形态，引入后本地安全设计失去意义
- **多用户协作交互**（PR 评审、评论、审批）

### 首版不做

- 逐行 blame、行内标注等 GitLens 类深度追溯功能
- **界面语言切换（i18n）**——界面文案固定英文，中文读者由 `README.zh-CN.md` 承接。一个只读三区块界面上大约 30 条短文案，做成可切换要引入文案表、语言协商与一份要跟着改的测试夹具，而它换来的只是把两个读者里的一个从 README 挪到界面上
