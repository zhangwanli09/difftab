# difftab 文档写作规范

**这份 skill 只承载流程与顺序，规则的事实来源是 [`docs/README.md`](../../../docs/README.md) 与 CLAUDE.md 第 5 节「文档与注释」。** 两边不一致时以那两份为准，并顺手把这里改对——第三份会漂的文档正是这个仓库反复在收的东西。

## 为什么需要它

这个仓库的门禁很密（十几道，见 `docs/gates.md`），但**没有一道看得见文档**。半角逗号、汉字之间的硬换行、锚点链错、内容落错文件、同一条规则在两处各长一份，全部是「不报错、只是静默出错」。160 条提交里 92 条是 `docs`，这类改动是常态不是例外，所以它需要一套动作，而不只是一份可以事后查的规范。

## 第一步：判断这段内容落哪份

**别就近塞。** 各文件之间刻意不互相复述，塞错地方的代价不是当场的，而是下次改的时候只想得起一处。

| 你要写的是 | 落哪 |
|---|---|
| 一条规则，外加它失效时的机制 | `docs/design/<域>.md` |
| 实测输出、源码逐行核对的结论、被排除的做法 | `docs/decisions.md` **对应那一节**（七节之一，别在文件末尾另起一摊） |
| 怎么验、某道门禁挡住哪条静默故障、fixture 契约 | `docs/gates.md` |
| 一次性的过程记录、发布踩坑、未完事项 | `docs/history.md`（**是记录不是约束**：其中沉淀出的通用规则要么进 `decisions.md`、要么进 CLAUDE.md 红线，不靠读日志生效） |
| 违反后不报错、只是静默出错的条目 | CLAUDE.md 第 5 节，**同时留在 `design/` 里**——这层重复是刻意的，等读者路由到 `design/` 时已经晚了 |
| 发布的步骤 | `RELEASING.md` |
| 对外的产品承诺与贡献者须知 | `CONTRIBUTING.md` 与 `.github/` |

「改这块 → 读哪份」的**读侧**路由表只有一份，在 CLAUDE.md 第 4 节。**不要在 `docs/` 里再养一份**：两份并列的路由表没有任何门禁看得见，而它已经漂过一轮。

## 第二步：按规范写

### 标点与排版

- **中文标点按 GB/T 15834 用全角**：`，；：（）「」` 不写半角。三类**不**转：数字千分位（`1,048,945`）、成段英文引文的内部、代码块与行内代码里的一切。
- **破折号 `——` 占两个字位，前后不加空格。**
- **段落不要在两个汉字之间硬换行**——markdown 会把那个换行渲染成一个可见空格，源码里看不出来，只有在网页上才看得见。
- **语言分工**：界面文案一律英文，`docs/`、代码注释、测试名仍中文。

### CLAUDE.md

- **预算 ≤ 200 行，且一条规则占一行。两半必须同时成立**：行数能被「把十几条规则塞进一个 bullet」轻易做低，那样的文件行数好看而实际不可扫读。
- **禁止再给它补字节 / KB 上限**：中文 UTF-8 3 字节一字，字节维度远早于行数触顶，一旦并设，真正生效的就只剩字节，而省字节最省事的手段恰恰是把多条规则挤进一行长句。
- **超预算时先问「这段能不能下沉到 `docs/`」，而不是接着往下写。** 红线与路由表不参与裁剪，可裁的是能从代码库或 git log 推导出来的内容。
- **会过期的东西一律不进**：版本号、发布日期、进度、「某阶段已收口」——事实来源分别是 `package.json`、`git log`、`docs/history.md`，而常驻上下文里的过期叙述不会有人主动想起来删。

### decisions.md

- **按小节拆，不按文件拆**，入口一律是锚点；七个小节各自带本域的「被排除的做法」分表，`design/` 一律以 `../decisions.md#<小节>` 链进去。
- **小节标题写成纯词组，不带括号与标点**——锚点是靠标点剥离规则算出来的，链错了不会有任何东西响。
- **每一节都要能被单独读懂**：锚点只保证一眼落到那一节，读取的最小单位仍是整个文件。

### design/

- 按领域分文件，**一份撑到约 15k 字符就再拆**。拆分的全部意义是让「只读用得着的那份」在工具层面真的只付一份的代价；一份长回四五万字符，路由表就退化成一句安慰。

### 两份 README

- **`README.zh-CN.md` 不是自动生成的**，只改英文那份不会有任何门禁变红。**要改就两份一起改。**
- **特性列表只收差异点，不是功能清单**：加了新功能默认**不动** README，除非它本身就是个卖点。功能的事实来源是 `docs/spec.md`。
- **不建 `CHANGELOG.md`**：GitHub Releases 的 notes 就是变更日志。

### 代码注释

- **不得反指文档。** 方向是单向的：CLAUDE.md 第 4 节回答「改这块 → 读哪份」，注释只写理由与机制，不写「见 `docs/xxx.md`」。写一条不报错，但它会像退役前那 250 处 `spec §x` 一样长回来，而指错时没有任何东西会响。
- 本仓库的注释承载知识（后端产物刻意保留它们以便审计），所以注释的密度与措辞按周围代码来，别当成可有可无的装饰。

### 不要重建的东西

逐条勾选的验收清单、阶段排期。阶段推进已经结束，「怎么验」由 `docs/gates.md` 以「门禁 → 挡住哪条静默故障」的形式承接；再开一份带 `[x]` 的清单，等于把一个没有读者的东西重新养起来。

## 第三步：跨文件同步

这几处**并列存在且互不引用**，改一处不动另一处不会有任何东西变红：

- **新增 `package.json` script** → CLAUDE.md 第 3 节命令表 + `CONTRIBUTING.md` 的 Gates 表（对外那份是子集，不必全抄，但不能与第 3 节相左）+ `docs/gates.md` 的门禁表（它挡什么、在哪跑）。
- **改 CLAUDE.md 第 6 节「明确不做」** → `CONTRIBUTING.md` 与 `.github/` 里给外部读者的那份产品承诺跟着改。
- **新增或改动一道门禁** → `docs/gates.md` 的门禁表必须同时回答「挡住哪条静默故障」与「在哪跑」，只写命令名等于没写。

## 第四步：收尾自检

```bash
node .claude/skills/docs-conventions/scripts/check-docs.mjs        # 默认查工作区改动过的文件
node .claude/skills/docs-conventions/scripts/check-docs.mjs --all  # 查全仓
```

脚本查八件有固定判据的事：半角标点贴着汉字、半角括号包着汉字、破折号旁的空格（含折在行首行尾那种）、汉字间硬换行、CLAUDE.md 行预算、`decisions.md` 小节标题里的标点、跨文件锚点打不打得中，外加源码注释里的文档反指。它会剥掉代码块与行内代码，所以千分位和 `a, b` 这类不会误报；**成段英文引文里的半角标点它分不出来**，报出来的每一条都要自己看一眼。

**然后逐行读 diff**（`git diff -- '*.md'`）。脚本看不见的恰恰是最贵的四类：

1. 这段内容落错了文件（第一步那张表）；
2. 同一件事在两处各长了一份（尤其 `design/` 与 `decisions.md` 之间，以及任何一张被复述的表）；
3. 列表层级、缩进、表格列数坏掉；
4. 语义写反了——「禁止 X」写成「必须 X」这类，改动越小越容易漏。

这一步没有替代品：**纯注释、纯文档的改动跑完全套门禁一条都不红。**

## 什么时候停下来问人

- CLAUDE.md 要超 200 行，且看不出哪段能下沉；
- 要新开一份 `docs/design/` 文件，或给 `decisions.md` 新开一个域的小节；
- 要往 CLAUDE.md 第 5 节红线里加或删条目（收录判据是「违反后不报错、只是静默出错」，这个集合的进出是结构性决定）；
- 要改第 6 节「明确不做」——那是架构性承诺，破例等于变成另一个产品。

## 一处已知的存量偏差

`src/**/README.md`、`test/**/README.md` 与 `lefthook.yml` 的注释成片使用半角逗号、半角括号与两边带空格的破折号，`docs/`、CLAUDE.md、两份 README 则是全角。脚本会把它们全报出来。**这是存量，不要顺手全改**——一次性重排会让一个纯格式提交盖住真正的改动。只修你这次确实改到的那几行，或者单开一个 `docs:` 提交专门收它。
