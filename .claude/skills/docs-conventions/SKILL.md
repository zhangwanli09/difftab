# difftab 文档写作规范

**这份 skill 只承载流程与顺序，一条规则原文都不复制。** 规则的事实来源是 [`docs/README.md`](../../../docs/README.md) 与 CLAUDE.md 第 5 节「文档与注释」。在这里再抄一份不会有任何东西变红，而那正是第四份会漂的文档——`docs/README.md` 自己就写着这一条。

## 为什么需要它

这个仓库的门禁很密（十几道，见 `docs/gates.md`），但**没有一道看得见文档**。半角逗号、汉字之间的硬换行、锚点链错、内容落错文件、同一条规则在两处各长一份，全部是「不报错、只是静默出错」。160 条提交里 92 条是 `docs`，这类改动是常态不是例外，所以它需要一套动作，而不只是一份可以事后查的规范。

## 第一步：判断这段内容落哪份

**别就近塞**——塞错地方的代价不是当场的，而是下次改的时候只想得起一处。

判据表在 [`docs/README.md` 的「内容落哪份文件」](../../../docs/README.md#内容落哪份文件)，动手前整节读完——它同时给出 `design/` 何时再拆、`decisions.md` 为什么按小节而不按文件拆、以及为什么不重建逐条勾选的验收清单。

「改这块 → 读哪份」的**读侧**路由表则只有一份，在 CLAUDE.md 第 4 节，**不要在 `docs/` 或本文件里再养一份**。

## 第二步：按规范写

规则原文在两处，都要读：

- [`docs/README.md` 的「四条写作约定」](../../../docs/README.md#四条写作约定)——全角标点（**范围是全仓的中文，不止 `docs/`**）、破折号、汉字间硬换行、`CLAUDE.md` 的 ≤ 200 行预算、读侧路由表唯一、红线与 `design/` 刻意重复。
- CLAUDE.md 第 5 节「文档与注释」——注释不得反指文档，以及为什么纯注释改动只能靠逐行读 diff；第 7 节——两份 README 要一起改、不建 `CHANGELOG.md`、README 特性列表只收差异点。

## 第三步：跨文件同步

这几处**并列存在且互不引用**，改一处不动另一处不会有任何东西变红：

- **新增 `package.json` script** → CLAUDE.md 第 3 节命令表 + `CONTRIBUTING.md` 的 Gates 表 + `docs/gates.md` 的门禁表。
- **新增或改动一道门禁** → `docs/gates.md` 的门禁表必须同时回答「挡住哪条静默故障」与「在哪跑」，只写命令名等于没写。
- **改 CLAUDE.md 第 6 节「明确不做」** → `CONTRIBUTING.md` 与 `.github/` 里给外部读者的那份产品承诺跟着改。

## 第四步：收尾自检

```bash
node .claude/skills/docs-conventions/scripts/check-docs.mjs        # 默认查工作区改动过的文件
node .claude/skills/docs-conventions/scripts/check-docs.mjs --all  # 查全仓
```

脚本查八件有固定判据的事：半角标点贴着汉字、半角括号包着汉字、破折号旁的空格（含折在行首行尾那种）、汉字间硬换行、CLAUDE.md 行预算、`decisions.md` 小节标题里的标点、跨文件锚点打不打得中，外加源码注释里的文档反指。它会剥掉代码块与行内代码，所以千分位和 `a, b` 这类不会误报。

Markdown 之外的文件（`.ts` / `.js` / `.css` / `.json` / `.yml`）同样查标点，但**先把语法位置遮掉、只留注释与字符串**：所以 `{ 慢写: x }` 与 `:root` 不会被报，YAML 里 `run:` 底下那段 shell / JS 也不当散文看。**成段英文引文里的半角标点它分不出来**，报出来的每一条都要自己看一眼。

**然后逐行读 diff**（`git diff`）。脚本看不见的恰恰是最贵的四类：

1. 这段内容落错了文件（照第一步指的那张判据表再核一遍）；
2. 同一件事在两处各长了一份（尤其 `design/` 与 `decisions.md` 之间、本文件与 `docs/README.md` 之间，以及任何一张被复述的表）；
3. 列表层级、缩进、表格列数坏掉；
4. 语义写反了——「禁止 X」写成「必须 X」这类，改动越小越容易漏。

这一步没有替代品：**纯注释、纯文档的改动跑完全套门禁一条都不红。**

## 什么时候停下来问人

- CLAUDE.md 要超 200 行，且看不出哪段能下沉；
- 要新开一份 `docs/design/` 文件，或给 `decisions.md` 新开一个域的小节；
- 要往 CLAUDE.md 第 5 节红线里加或删条目（收录判据是「违反后不报错、只是静默出错」，这个集合的进出是结构性决定）；
- 要改第 6 节「明确不做」——那是架构性承诺，破例等于变成另一个产品。
